# Learna 文档导航

本目录存放 Learna 的正式设计文档与工程规范。约定「边开发边沉淀」：随开发将确定文档放入对应目录。

## 文档优先级

```text
项目负责人明确指令 > docs/AGENTS.md > docs/工程规范/* > 现有代码风格
```

任务要求、硬约束、工程规范或正式设计文档之间冲突时，必须暂停并向项目负责人报告，不得自行选择性忽略。

## 目录结构

| 目录 / 文件 | 性质 | 说明 |
|---|---|---|
| `AGENTS.md` | **硬约束** | Agent 开发硬约束，任务前必读；详细规范见 `工程规范/` |
| `工程规范/` | 工程规范 | 开发工作流、代码风格、架构约束、领域不变量、安全与 AI、数据库与 API、测试与验证、变更管理、交付报告模板、AI 任务执行模板 |
| `产品需求/` | 正式设计文档 | 《Learna 产品需求规格说明书 V1.0》——需求基线，已确认 / 设计建议 / 待决策状态标记 |
| `架构设计/` | 正式设计文档 | 《Learna 系统设计方案 V1.0》——系统边界、领域模型概述、核心流程、调度设计、API 契约原则 |
| `数据库设计/` | 正式设计文档 | 《Learna 领域模型与 ERD 设计文档 V1.0》——实体、关系、数据字典、索引、删除策略、实施优先级 |
| `接口契约/` | 确定文档 | API 契约三层：全局规范（README）、业务接口清单、openapi.yaml（仅已确认接口）、设计记录（接口审计） |
| `开发指南/` | 确定文档 | 开发环境、约定与流程（随开发沉淀） |
| `架构决策/` | 确定文档 | 架构决策记录（ADR）；修改领域规则前必须先在此登记 |
| `历史参考/` | **历史参考** | 早期未定稿文档（docx），仅供讨论参考，不作为实现依据 |

## 新人 / Agent 阅读顺序

1. `产品需求/Learna产品需求规格说明书V1.0.md`——产品要做什么、版本边界。
2. `架构设计/Learna系统设计方案V1.0.md`——系统怎么组织、核心业务流程。
3. `数据库设计/Learna领域模型与ERD设计文档V1.0.md`——实体关系与数据语义。
4. `AGENTS.md` + `工程规范/`——动手前必须遵守的硬约束与工程规则。

## 维护约定

- 修改 API、数据库结构或重要架构设计时，必须同步更新对应确定文档。
- 修改领域规则必须先向 `架构决策/` 提交 ADR 或设计变更说明，再改代码。
- `工程规范/` 与 `AGENTS.md` 冲突时以 `AGENTS.md` 为准；工程规范与正式设计文档冲突时暂停并报告。
- 不得为了通过检查而删除、弱化或跳过规范。
- `历史参考/` 下的文档保持原样，仅作历史参考。
