# Learna 接口契约

**状态：** 已定稿（全局规范）；业务接口随模块设计逐个冻结  
**依据：** PRD V1.0、TAD V1.0 §6、ERD V1.2、`工程规范/数据库与API规则.md`  
**层次：** 本目录按三层组织——① 全局 API 规范（本文）→ ② 业务接口目录（`接口清单.md`）→ ③ 逐模块 DTO 与接口行为（`openapi.yaml` + `设计记录/`）

---

## 1. 版本策略

- 业务接口统一挂在 **URL 路径前缀 `/api/v1`** 下（ADR-001）。
- 健康检查 `/healthz`、`/readyz` 属基础设施端点，**不版本化**。
- 破坏性变更升 `/api/v2`；v1 内只做向后兼容的增量演进（新增可选字段、新增端点）。
- 前端 `baseURL` 为 `/api/v1`；dev 代理与 nginx 均**透传完整 URI**，不做前缀剥离。

## 2. 命名规范

- JSON 字段名统一 **snake_case**。
- 资源路径使用 **kebab-case 复数名词**（TAD §6.3 方向）：`/learning-sessions`、`/learning-contents`、`/daily-goals` 等。
- 项目内子资源采用嵌套路径（`/projects/{project_id}/tasks`），全局查询用独立资源 + 过滤参数。
- 现有过渡资源 `/records` 保留至正式 LearningSession 契约落地（见接口清单状态标注），**不得**将其改名冒充正式契约。

## 3. HTTP 方法语义

| 方法 | 语义 | 说明 |
|---|---|---|
| GET | 安全读取 | 可缓存，无副作用 |
| POST | 创建 | 创建资源 / 触发动作 |
| PATCH | 部分更新 | 三态语义（ADR-002）：字段**缺失**＝不变；显式 **null**＝置空；**值**＝更新 |
| PUT | 全量替换 | 保留给未来「整体覆盖」场景，当前无使用 |
| DELETE | 删除 | 删除语义按模块定义（软删除/物理删除必须显式约定）；学习规划模块采用四层语义（ADR-006）：draft 容器物理删、已生效结构不提供删除、任务软删、成果禁删 |

## 4. 统一响应信封

成功与失败响应结构一致（ADR-003）：

```json
{
  "code": "200",
  "message": "success",
  "data": {},
  "request_id": "b3f1c2e4-..."
}
```

| 字段 | 类型 | 约定 |
|---|---|---|
| `code` | string | `"200"` 表示成功；其余为稳定业务错误码（见 §5），**禁止随意改字符串** |
| `message` | string | 人类可读信息；5xx 对外只给概括，细节进服务端日志 |
| `data` | any / null | 业务数据；失败时为 null |
| `request_id` | string | 请求追踪 ID（UUID v4，由中间件生成）；**成功与失败响应都必填实际值** |

- **HTTP 状态码表达协议层结果，业务 `code` 表达业务错误类别，二者不互相替代**（TAD §6.2）。
- `code` 采用字符串（延续现有信封方向；TAD §6.2 示例中的数字仅示意）。

## 5. 状态码与错误码

| HTTP | 业务 code | 场景 |
|---|---|---|
| 200 | `200` | 成功 |
| 401 | `UNAUTHORIZED` | 未携带/无效凭证 |
| 401 | `TOKEN_ERROR` | Token 构造/内部密钥异常 |
| 403 | `FORBIDDEN` | 已认证但无权限 |
| 404 | `NOT_FOUND` | 资源不存在**或不属于当前用户**（防存在性探测） |
| 409 | `CONFLICT` | 状态/并发冲突 |
| 422 | `VALIDATION_ERROR` | 入参校验失败 |
| 429 | `RATE_LIMITED` | 限流 |
| 500 | `INTERNAL_ERROR` / `HASH_ERROR` | 内部故障 |
| 502 | `UPSTREAM_ERROR` | 上游服务失败 |

- **409 的唯一例外**：删除类端点被未确认的子项阻断时，`data` 可携带结构化影响面 —— `{ "impact": { "milestones": 3, "tasks": 7 }, "hint": "..." }`；其余 409 的 `data` 仍为 `null`（ADR-006 / D-22）。

## 6. 分页

- 查询参数：`page`（≥1，默认 1）、`page_size`（1–100，默认 10），非法值收敛到边界。
- 响应：`{ "items": [...], "total": 123 }`。
- 排序由后端固定（学习记录按 `created_at DESC`）；开放排序/游标分页属**待决策**。

## 7. 认证与授权

- 认证：`Authorization: Bearer <JWT>`（HS256，有效期 7 天，`sub` 为用户 UUID）。
- 免认证端点：`POST /api/v1/auth/register`、`POST /api/v1/auth/login`、`GET /healthz`、`GET /readyz`。
- 授权模型（首版）：**个人数据隔离**——所有业务资源按 `owner/user_id` 归属，后端逐请求做所有权校验；越权访问返回 404。
- 前端 401 统一跳登录页；登录/注册接口的 401 不触发跳转。

## 8. 时间格式

- 时间戳：ISO 8601 / RFC 3339（UTC，带 `Z` 后缀），如 `2026-11-27T03:20:00Z`。
- 业务日期：`YYYY-MM-DD`，不得伪装成时间戳（正式接口适用）。

## 9. 契约维护规则

- **`openapi.yaml` 是机器可读契约源**；API 变更必须同步 `openapi.yaml` 与 `接口清单.md`（`数据库与API规则.md` §2）。
- 未确认的业务接口**禁止**写入 `openapi.yaml`；未确定事项在 `设计记录/` 标记 **待决策**，不得擅自假设。
- 修改领域规则前先在 `架构决策/` 登记 ADR。
- OpenAPI 的 CI 自动校验：**待决策**（TAD §6.1 要求纳入 CI，接入方式未定）。

### 9.1 契约最小承诺（ADR-007）

**契约只承诺「当前有执行者」的能力**。判断一条内容该不该进契约时按序提问：

1. 这个字段有没有生产者？没有 → 不进契约（例：`completion_rule` / `target_definition`，唯一生产者是尚未启动的 AI 线）。
2. 这个能力有没有消费者？没有 → 不进契约（例：`deleted_at`，v1 无回收站，软删仅为数据留存）。
3. 这个参数有没有依据？无索引或产品依据 → 不开放（例：列表 `sort` 参数、多值 `status`）。

配套两条硬约定：

- **默认值必须写进 schema**（`default:`），不得留给实现期猜测；取值必须有 PRD 或 ERD 依据（例：`importance_level=3` 取自 PRD §5.1「I3 = 普通」）。
- **列表默认序固定**，并以 `id` 作 tiebreaker 保证分页稳定；排序变更视为契约变更。
