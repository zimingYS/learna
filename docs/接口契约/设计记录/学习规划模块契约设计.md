## 1. 领域实体与不变量

### 1.1 LearningProject（学习项目）

| 维度 | 内容 | 依据 |
|---|---|---|
| 字段 | name、description、project_type（study / skill_development / challenge / deliverable）、status（六值见 §2.1）、importance_level(1–5)、importance_override_until、deadline_type（none / soft / fixed）、deadline_at、archived_at、reopened_at | ERD §5.1；status 枚举见 D-16 |
| 不变量 | `importance_level ∈ [1,5]`；`deadline_type=none → deadline_at IS NULL`；`soft/fixed → deadline_at IS NOT NULL`；`fixed` 日期修改必须走特殊确认流程；归档不删除子数据 | ERD §5.1 约束、D-05 |
| 生命周期 | 草稿 / 进行中 / 暂停 / 已完成 / 已归档；已完成与已归档可重新开启，保留历史数据 | PRD §4.3 |
| 删除 | 草稿可直接删除（级联物理删除规划数据）；已实施项目首选归档，强制删除须走 `purge` 并重输项目名 | D-02a/D-02b（§6） |
| 创建默认值 | `status=draft`、`project_type=study`、`importance_level=3`、`deadline_type=none`（此时 `deadline_at` 必空） | PRD §5.1「I3 = 普通」；ERD 约束；D-19 |
| 归属 | `owner_id` → 当前用户；越权访问按 404 处理 | PRD §4.1（个人工具、无共享）、全局规范 §7 |

### 1.2 ProjectGoal（项目目标）

| 维度 | 内容 | 依据 |
|---|---|---|
| 字段 | title、description、goal_type（outcome / performance / completion）、target_definition(JSONB)、status（active / achieved / cancelled）、target_at、parent_goal_id（可空自引用） | ERD §5.1；parent_goal_id 为 D-06 决策补列 |
| 不变量 | 目标属于项目；`target_definition` **v1 不对外暴露、不写入**，DB 列恒为 NULL，关键字段将来另设列 | ERD §5.1 自注「关键字段应另设列」；D-08 |
| 层级 | 每项目最多一个主目标（`parent_goal_id IS NULL`）；子目标挂主目标下，**上限两层**；不得跨项目、自引用或成环 | PRD §4.5「一个主要目标 + 多个子目标」；D-06 |
| 生命周期 | active → achieved / cancelled；achieved / cancelled → active（回退，用于误判修正） | ERD 字段枚举；D-07b |
| 删除 | 物理删除；`achieved` 拒绝删除（409，成果保护），`active` / `cancelled` 允许；同事务删 GoalStage 关联行 | D-07a（§6） |
| 与 Stage 关系 | GoalStage 多对多，`contribution ∈ {primary, supporting}`，复合主键 `(goal_id, stage_id)` | ERD §3、§5.1 |

### 1.3 Roadmap（项目路线，版本化）

| 维度 | 内容 | 依据 |
|---|---|---|
| 字段 | project_id、version、status（draft / active / superseded）、source（user / ai / template）、change_summary、confirmed_at、created_by | ERD §5.1 |
| 不变量 | `UNIQUE(project_id, version)`；**一个项目最多一个 active roadmap**；已被替代版本保留历史 | ERD §5.1 约束、§8（Roadmap 标记 superseded，保留路线历史） |
| 生命周期 | draft → active（用户确认，写 `confirmed_at`）→ superseded（被新版本确认时替换）；draft 可删除（物理），superseded 为只读历史 | ERD 字段枚举；PRD §4.5（AI 规划须用户确认）；D-12 |

### 1.4 Stage（路线阶段）

| 维度 | 内容 | 依据 |
|---|---|---|
| 字段 | roadmap_id、name、description、sequence_no、status（pending / active / completed / skipped）、completion_rule(JSONB 可选，**v1 不入契约**)、completion_method（user / system_confirmed / ai_suggested，v1 只产 `user`）、started_at、completed_at | ERD §5.1；D-08 |
| 不变量 | `UNIQUE(roadmap_id, sequence_no)`；推荐顺序不代表强制线性（可跳过、提前进入、返回） | ERD §5.1 约束；PRD §4.4 |
| 生命周期 | pending → active → completed / skipped；跳过与返回（重新激活）是 PRD 明确允许的行为。**状态动作要求所属路线为 active**（draft 路线是编辑区、superseded 只读，均拒绝 409） | PRD §4.4；D-09 |
| 删除 | 仅 draft 路线可删，**物理删除**（草稿阶段无执行历史）；子项按 `cascade` 显式确认（§6） | PRD §4.4「可删除 AI 生成的阶段」；D-09 |
| 完成判定 | 完成条件可选；无完成条件时由用户手动确认；AI 判断只作建议，最终用户确认 | PRD §4.4 |

### 1.5 Milestone（里程碑）

| 维度 | 内容 | 依据 |
|---|---|---|
| 字段 | stage_id、title、description、status（pending / in_progress / completed / skipped）、completion_rule(JSONB 可选，**v1 不入契约**)、completed_at | ERD §5.1；D-08 |
| 关系 | 里程碑属于阶段；`Project → Stage → Milestone → Task` 为推荐层级 | ERD §5.1；PRD §4.5 |
| 删除 | 仅 draft 路线可删，物理删除；关联任务**解挂保留**（清 `milestone_id`，保留 `stage_id`） | ERD §5.1 `milestone_id` 可空；D-10 |

### 1.6 LearningTask（学习任务）与 TaskDependency

| 维度 | 内容 | 依据 |
|---|---|---|
| 字段 | project_id、milestone_id（可空）、stage_id（可空）、title、description、status（todo / in_progress / blocked / completed / cancelled）、priority(1–5)、due_at、estimated_minutes(≥0)、completed_at、created_source（user / ai / template） | ERD §5.1；stage_id 为 D-05 决策补列 |
| 不变量 | 任务必属项目；`milestone_id` / `stage_id` 均可空（支持简单项目与阶段直挂）；两者同时存在时，阶段须与里程碑所属阶段一致 | ERD §5.1；PRD §4.5；D-05 |
| 依赖 | `(task_id, depends_on_task_id)` 复合主键；禁止自依赖；两任务须同属一个项目（领域服务校验）；首版禁止环路 | ERD §5.1 TaskDependency；PRD §4.5（首版支持简单前置依赖） |
| 删除 | 软删除（唯一软删对象，因其承载执行历史）；**任务永不随上层结构删除而消失**：删阶段/里程碑/路线时解挂引用，任务行保留 | ERD §8「保留执行历史引用」；D-09/D-10/D-12 |
| 创建默认值 | `status=todo`、`priority=3`、`created_source=user`；`milestone_id` / `stage_id` / `due_at` / `estimated_minutes` 均可空 | ERD §5.1；D-19 |
| 软删除连带规则 | 软删行**不计入**列表查询、依赖环路检测、`DeletionConflict` 影响面计数与结构解挂范围 | D-17（否则 impact 计数永远清不掉） |

## 2. 状态与流转

> 原则：PRD/ERD 明确的状态与行为写入契约；边缘迁移由 §2.5 统一规则推导并声明外推（ADR-007）。

### 2.1 项目状态机（PRD §4.3）

| 当前 | 动作 | 目标 | 副作用 | 依据 |
|---|---|---|---|---|
| 草稿 | activate（开始） | 进行中 | — | PRD §4.3「已创建，尚未正式开始」 |
| 进行中 | pause | 暂停 | — | PRD §4.3 |
| 暂停 | resume | 进行中 | — | PRD §4.3 |
| 进行中 / 暂停 | complete | 已完成 | — | PRD §4.3；暂停→已完成 由 D-01 开放 |
| 已完成 | reopen | 进行中 | `reopened_at = now` | PRD §4.3「已完成允许重新开启」 |
| 草稿 / 进行中 / 暂停 / 已完成 | archive | 已归档 | `archived_at = now`；不级联删除子数据 | PRD §4.3；ERD D-05 |
| 已归档 | reopen | 进行中 | `reopened_at = now`，清空 `archived_at` | PRD §4.3「已归档允许重新开启」 |
| 草稿 | delete | （行消失） | 级联物理删除规划数据（单事务） | D-02a |
| 任意状态 | purge（强制删除） | （行消失） | 须重输 `confirm_name`；`status=deleting` 拦截并发写 → 级联删 → 删项目行 | ERD §8.1；D-02b |

未定义迁移一律 409 `CONFLICT`。**D-01 已决策**的三条边缘迁移：

| 边缘迁移 | 结论 | 理由 |
|---|---|---|
| 暂停 → 已完成 | 开放（`complete` 接受 paused） | 目标达成时不应强制先 resume 再 complete |
| 草稿 → 已归档 | 开放（`archive` 接受 draft） | 「想了个项目又放弃」，避免为归档伪造一次启动 |
| 已完成 → 暂停 | 拒绝（409） | 完成是结果态；回退须走 reopen → pause，保留两步痕迹 |

**枚举字面值（D-16 已决策：合并六值）**：PRD §4.3「确认采用五种状态」= 草稿/进行中/暂停/已完成/已归档；ERD §9「状态枚举建议」= `active / paused / completed / archived / deleting`（无 draft、多 deleting）。两处各有依据 → 合并为 `draft / active / paused / completed / archived / deleting`。`deleting` 只在 `purge` 事务内部作为并发写保护标记存在，**不对外持久可见**：服务端拒绝任何把项目写成 `deleting` 的常规写入（含 PATCH / 动作端点），否则会产生僵尸态。

### 2.2 目标状态（ERD 字段枚举）

| 当前 | 动作 | 目标 | 依据 |
|---|---|---|---|
| active | PATCH status | achieved / cancelled | ERD status 枚举 |
| achieved | PATCH status | active（误判修正） | D-07b |
| cancelled | PATCH status | active（重新启用） | D-07b |
| achieved | PATCH status | cancelled | **拒绝 409**（先回 active 再取消，保留判定的两步痕迹） |
| 任意 | DELETE | （行消失） | `achieved` 拒绝 409；见 §6 |

### 2.3 路线状态（ERD §5.1）

| 当前 | 动作 | 目标 | 副作用 | 依据 |
|---|---|---|---|---|
| draft | confirm（用户确认） | active | `confirmed_at = now`；同项目原 active → superseded（单事务） | ERD 字段；PRD §4.5「生成内容需经用户确认」 |
| active | —（被新版本确认时被动 superseded） | — | 由 confirm 流程原子完成 | ERD「最多一个 active」 |
| draft | delete | （行删除） | 级联物理删除 stage/milestone；任务解挂；版本号空档不复用 | D-12（§6） |
| superseded | 任意写操作 | — | **拒绝 409**（历史只读） | ERD §8「保留路线历史」 |

### 2.4 阶段状态（PRD §4.4）

**准入：** 状态动作要求所属路线 `status=active`；draft 路线（编辑区）与 superseded 路线（只读）一律 409。这与「删除仅限 draft 路线」互斥，因此 `skip`（放弃执行）与 `delete`（编辑修正）不会产生二选一的歧义。

| 当前 | 动作 | 目标 | 副作用 | 依据 |
|---|---|---|---|---|
| pending | start | active | `started_at = now` | PRD §4.4「可提前进入」 |
| pending / active | skip | skipped | — | PRD §4.4「可跳过」 |
| active | complete | completed | `completed_at = now`，`completion_method = user` | PRD §4.4「手动确认完成」 |
| completed / skipped | reactivate（返回） | active | **清空 `completed_at`；`started_at` 保持不变** | PRD §4.4「可返回阶段」；D-18 |

**幂等与准入补全：** 对已处于目标状态的资源调用动作端点（如 `pending` 上 `start`、`active` 上 `reactivate`）返回 200 且不改任何字段（不刷新时间戳）；`completed` 阶段禁止 `skip`，须先 `reactivate`（与 §2.5 规则 3 一致）。

### 2.5 里程碑 / 任务状态（D-11 / D-18，ADR-007）

**统一迁移规则**（三资源同构，不逐项列举 5×5 矩阵）：

1. **允许跳过中间态**：未完态可直接进入终态（`todo → completed`、`pending → completed`），对应 PRD §4.4「不强制严格顺序」。
2. **允许向未完态回退**：终态可回到 `todo` / `pending` / `in_progress`（撤销误操作、重新打开），对应 PRD §4.3「重新开启保留既有数据」。
3. **终态之间不直转**：`completed ↔ cancelled`、`completed → skipped`、`skipped → completed` 一律 409；须先回退再转，保留判定的两步痕迹（与 D-07b 拒绝 `achieved → cancelled` 同理）。
4. **同态提交幂等 200**：`PATCH {status: 当前值}` 不报错、不改任何字段（**不刷新时间戳**）。
5. **时间戳副作用**：进入 `completed` 写 `completed_at = now`；离开 `completed` 置 `completed_at = NULL`；`started_at` 首次写入后不再变更、也不清空。

由此得到的合法边（枚举值来源 ERD §5.1）：

| 资源 | 枚举 | 允许的迁移 |
|---|---|---|
| Milestone | pending / in_progress / completed / skipped | `pending → in_progress / completed / skipped`；`in_progress → pending / completed / skipped`；`completed → pending / in_progress`；`skipped → pending / in_progress` |
| LearningTask | todo / in_progress / blocked / completed / cancelled | `todo → in_progress / blocked / completed / cancelled`；`in_progress → todo / blocked / completed / cancelled`；`blocked → todo / in_progress / completed / cancelled`；`completed → todo / in_progress`；`cancelled → todo / in_progress` |

**外推声明：** PRD §4.4 的「可跳过、可提前进入、可返回」只明文约束 Stage；本规则按同构原则外推到 Milestone / Task，属设计决策而非 PRD 明文，记入 ADR-007。

**固有损失（记入 ADR-007）：** `completed_at` 在离开终态时被清空，且 ERD 无状态历史表，因此 **v1 无法回答「完成过几次」「曾于何时完成」**。若后续需要，须新增 `stage_status_history` / `task_status_history`。

## 3. 资源路径决策

| 资源 | 路径 | 决策理由 |
|---|---|---|
| 项目 | `/api/v1/projects` | TAD §6.3 方向；个人数据隔离，无跨用户共享 |
| 目标 | `/api/v1/projects/{project_id}/goals` | 目标强属项目（ERD FK） |
| 路线 | `/api/v1/projects/{project_id}/roadmaps` | 路线版本化，历史需可查（ERD §8） |
| 阶段 | `/api/v1/projects/{project_id}/roadmaps/{roadmap_id}/stages` | **偏离** TAD §6.3 的 `/projects/{id}/stages` 建议：Stage 由 `roadmap_id` 决定归属，嵌套在路线版本下才能保证版本隔离；TAD 明确「最终路径应在领域模型确定后冻结」 |
| 里程碑 | `/api/v1/projects/{project_id}/milestones?stage_id=` | 扁平项目级 + 过滤（TAD §6.3）；POST 时 `stage_id` 必填（ERD） |
| 任务 | `/api/v1/projects/{project_id}/tasks` | 扁平项目级；`milestone_id` 可空（ERD）；避免五层嵌套 |
| 依赖 | `/api/v1/projects/{project_id}/tasks/{task_id}/dependencies` | 依赖以任务为主语（ERD TaskDependency） |
| 项目删除 | `DELETE /projects/{id}`（草稿）+ `POST /projects/{id}/purge`（强制） | 两种语义分离：常规删除是幂等资源操作；强制删除需确认体（项目名重输），且后续要承载学习记录处置选项（D-20），用动作端点避免 DELETE 语义膨胀 |

通用约定（沿用全局规范）：`/api/v1` 前缀；snake_case 字段；分页 `page`/`page_size`；PATCH 三态（ADR-002）；成功与失败信封一致（ADR-003）；越权 404。

**级联删除确认（D-09/D-12 统一形态）**：带子项的删除默认 **409**，`data` 返回影响面计数；调用方显式追加 `?cascade=true` 才执行级联。即 ERD §8.1 第 3–4 步「展示影响范围 + 二次确认」的轻量实现，不需要 `deleting` 中间态。

## 5. 认证、权限与错误码

- 所有端点要求 `Authorization: Bearer <JWT>`（全局规范 §7）；未认证 401 `UNAUTHORIZED`。
- 资源所有权：项目归属当前用户；子资源（goal/roadmap/stage/milestone/task/dependency）通过父链校验，不属于当前用户一律 **404 `NOT_FOUND`**（防存在性探测）。
- 422 `VALIDATION_ERROR`：字段校验失败（长度、枚举、`importance_level` 越界、截止日期约束、自依赖、环路、跨项目关联、GoalStage 整体替换中的重复 `stage_id` 或跨项目阶段等）。
- 409 `CONFLICT`：状态机非法迁移（含 §2.5 规则 3 的终态直转）、路线非 draft 却 confirm、阶段所在路线非 draft 却删除、superseded 路线写操作、目标 `achieved` 删除、并发冲突。
- **200 而非 409 的幂等场景**：状态动作落在已达到的目标态、`PATCH {status: 当前值}`、GoalStage 整体替换为相同集合——均返回 200 且不改任何字段。
- 409 的**删除影响面**：级联删除被拒时，`data` 携带 `{ "impact": { "milestones": 3, "tasks": 7 }, "hint": "..." }`（`DeletionConflict`，全局规范 §5 的明文例外）；其余 409 的 `data` 为 `null`。
- 404：资源不存在 / 越权 / 父资源不匹配（如 stage 不属于该 roadmap）。
- 5xx：沿用全局规范，不新增业务码。

## 6. 删除 / 归档 / 恢复策略

### 6.1 分层原则

删除语义由「该对象**是否已参与执行**」决定，不由对象类型决定（ADR-006）：

| 层 | 判据 | 对象 | 语义 |
|---|---|---|---|
| L1 编辑区 | 容器未生效（draft），从未参与执行 | draft 项目、draft 路线及其下 stage / milestone | **物理删除**（无历史可损，不引入 `deleted_at`） |
| L2 已生效结构 | 容器已 confirm | active / superseded 路线内的 stage / milestone | **不提供删除**，只用状态动作（superseded 全程只读） |
| L3 原子执行单元 | 自身承载执行历史（`completed_at`） | LearningTask | **软删除**（唯一软删对象） |
| L4 成果 | 达成事实 | achieved 目标、completed / archived 项目 | **不提供删除**，只能改状态或归档；项目须 `purge` 二次确认 |

### 6.2 逐资源策略

| 资源 | 默认操作 | 彻底删除 | 依据 |
|---|---|---|---|
| LearningProject | 归档（不级联） | ① 草稿：`DELETE` → 级联物理删除全部规划数据<br>② 已实施：`POST /purge` + 重输项目名，事务内置 `deleting` 拦截并发写 | PRD §4.2/§4.3；ERD §3.5、§8.1；D-02a/D-02b |
| ProjectGoal | 改状态（achieved / cancelled） | 物理删除 + 删 GoalStage 关联行；`achieved` 拒绝 409 | D-07a |
| Roadmap | superseded（保留历史） | 仅 `draft`；物理删除 + 级联 stage / milestone | ERD §8；D-12 |
| Stage | 状态动作（skip / complete 等） | 仅 draft 路线；物理删除；有子项须 `?cascade=true` | PRD §4.4；D-09 |
| Milestone | 状态动作（skip） | 仅 draft 路线；物理删除；关联任务解挂 | D-10 |
| LearningTask | 软删除（`deleted_at`） | **不提供**物理删除 | ERD §8 |
| TaskDependency | 物理删除（关联行） | 随任务软删、上层结构删除一并物理清理 | ERD TaskDependency |
| GoalStage | 物理删除（关联行） | 随目标 / 阶段 / 路线删除一并清理 | ERD GoalStage |

### 6.3 三条不变量

1. **任务不随上层结构消失（项目级删除除外）**：删阶段 / 里程碑 / 路线时任务行保留，仅将 `stage_id` / `milestone_id` 置 NULL（解挂），`project_id` 不变。**唯一例外是项目被删除**（`DELETE` 草稿 / `purge`）：任务无法脱离 `project_id` 存在（ERD §5.1 NOT NULL），故随项目一并删除。
2. **superseded 只读**：已废弃路线及其阶段 / 里程碑拒绝一切写操作（409）——这是 ERD §8「保留路线历史」的落地方式。
3. **`deleting` 不可写**：该值只由 `purge` 事务内部写入，随事务结束消失；任何常规写入（PATCH / 动作端点）置 `deleting` 一律拒绝，避免僵尸项目。

### 6.4 版本号分配

`UNIQUE(project_id, version)` 下新建路线取 `MAX(version) + 1`。draft 路线物理删除后版本号出现空档，**允许复用**：空档不承载任何已确认或已执行的历史。

## 7. 事务边界

| 操作 | 事务内容 |
|---|---|
| Roadmap confirm | 锁定同项目 active 路线 → 置 superseded → 目标路线置 active + `confirmed_at`（单事务，保证「最多一个 active」） |
| Project reopen | `status=进行中` + `reopened_at=now` + 清空 `archived_at`（单事务） |
| Project archive | `status=已归档` + `archived_at=now`；不触碰子数据（单语句） |
| Project extend-deadline | 校验 `deadline_type=fixed` → 更新 `deadline_at` → 写审计事件（含 reason，单事务） |
| Stage complete | `status=completed` + `completed_at=now` + `completion_method=user`（单事务） |
| Stage / Milestone / Task 状态变更 | 按 §2.5 校验迁移 → 写 `status` + 时间戳副作用（进 completed 写 now、离开置 NULL；`started_at` 只写一次）（单语句） |
| Task complete | `status=completed` + `completed_at=now`；离开 completed 时清空（单事务） |
| Dependency create | 校验两任务同项目且归属当前用户（**均未软删**）→ 环路检测（含新增边）→ 插入（单事务，防并发成环） |
| GoalStage replace | 校验目标存在、所有 `stage_id` 同属该项目且集合内无重复 → 删除该 goal 全部关联行 → 批量插入新集合（单事务） |
| Project draft delete | 校验 `status=draft` → 级联物理删 dependency / task / milestone / stage / goal_stage / roadmap / goal → 删项目行（单事务） |
| Project purge | 校验 `confirm_name == name` → `status=deleting` 加行锁拦截并发写 → 同上级联 → 删项目行 → 留结构化快照日志（单事务，对应 ERD §8.1 step 5–9） |
| Roadmap delete | 校验 `status=draft` 且 `cascade` 已确认 → 删 milestone → 任务解挂（清 `stage_id`/`milestone_id`）→ 删 goal_stage → 删 stage → 删 roadmap（单事务） |
| Stage delete | 校验路线 draft 且 `cascade` 已确认 → 删 milestone → 任务解挂（清 `stage_id`/`milestone_id`）→ 删 goal_stage → 删 stage（单事务） |
| Milestone delete | 校验路线 draft → 任务解挂（只清 `milestone_id`）→ 删 milestone（单事务） |
| Goal delete | 校验 `status ≠ achieved` → 删 goal_stage → 删 goal（单事务） |
| Task delete | `deleted_at` 标记 + 同事务物理删其依赖行（单语句组） |
