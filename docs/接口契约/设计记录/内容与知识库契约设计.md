## 1. 领域实体与不变量

### 1.1 LearningContent（学习内容，用户级资产）

| 维度 | 内容 | 依据 |
|---|---|---|
| 字段 | title、description、body、body_format、source_url、content_type、parent_id（自引用）、status、created_source | ERD §5.2 + ADR-009（body / body_format / source_url） |
| 不变量 | `title` 1–200；`description` ≤ 500；`body` ≤ 100 000 且空串归一为 `NULL`；`body_format ∈ {markdown, plain_text}`，默认 `markdown`；`source_url` 仅 `http(s)://` 且 ≤ 2048 | ADR-009 §2/§4/§7 |
| 归属 | `owner_id` → 当前用户；内容可跨项目复用，**不建 `(owner_id, title)` 唯一约束**（ERD §3.1） | ERD §3.1、§5.2 |
| 生命周期 | `active` ↔ `archived`；归档不影响已存在的项目关联 | ERD §5.2；M03 §6 |
| 删除 | 默认**归档**；`?purge=true` 走物理删除，前置条件见 §6.2 | ADR-006；§6 |
| `metadata` | v1 **不读写、恒 `NULL`**；请求体出现该字段 → 422 | ADR-009 §3；D-29 |

### 1.2 ContentRelation（内容关系）

| 维度 | 内容 | 依据 |
|---|---|---|
| 字段 | source_content_id、target_content_id、relation_type | ERD §5.2 |
| 枚举 | `prerequisite` / `related` / `contains` / `extends` / `alternative` | ERD §5.2 |
| 不变量 | `source ≠ target`；`UNIQUE(source, target, relation_type)`；两端同 `owner`；`prerequisite` 不得成环 | ERD §5.2；§5 |
| 方向 | **单向存储、双向查询**；对称关系也只存一行，查询时展开并标注 `direction` | D-25 |
| 删除 | 物理删除（关系无历史价值）；`purge` 内容时两端关系由外键 `CASCADE` 清理 | ADR-006；§6.2 |

### 1.3 ContentTag / LearningContentTag（标签）

| 维度 | 内容 | 依据 |
|---|---|---|
| 字段 | `content_tags`：name（≤60）、color（≤20，可选）；`learning_content_tags`：(content_id, tag_id) | ERD §5.2 |
| 不变量 | `UNIQUE(owner_id, name)`：用户私有词表，同名必须合并而非并存；内容与标签必须同 `owner` | ERD §5.2 |
| 关系形态 | 内容 ↔ 标签为多对多，**整体替换**语义（`PUT`），不做逐条增删 | D-28；§4.3 |
| 边界 | 标签只用于内容；题目↔知识点走 `question_knowledge_points`、成果↔技能点走 `artifact_content_relations`，**不共用** | ERD §5.2 |

### 1.4 ProjectContent（项目内的内容上下文）

| 维度 | 内容 | 依据 |
|---|---|---|
| 字段 | project_id、content_id、target_mastery_level(0–4)、current_status（五值）、priority(1–5)、auto_review_enabled、linked_at、achieved_at | ERD §5.2 |
| 不变量 | `UNIQUE(project_id, content_id)`；项目 owner 与内容 owner 必须同一人（服务层校验） | ERD §5.2 |
| 核心区分 | **同一内容在两个项目里可以分别是 `learning` 与 `achieved`**——状态是项目级的，不是内容的属性 | ERD §3.2 |
| 删除 | 解除关联 = 物理删该行；**不删内容本体**，也不动 `content_relations` | M03 §6；§6.2 |

## 2. 状态与流转

### 2.1 内容状态（`active` / `archived`）

| 迁移 | 触发 | 副作用 |
|---|---|---|
| `active → archived` | `DELETE /learning-contents/{id}` | 写 `status`、`updated_at`；保留 `project_contents` 与关系行 |
| `archived → active` | `PATCH` 的恢复动作 **不提供** | — |

**不提供「取消归档」**：归档是用户表达「这份内容我不再使用」的动作，误操作的正确修复是 `purge` 后重建（内容可重建，项目上下文与关系也可重建）。开放双向会引入「归档期间被排除的统计是否需要补算」的问题，v1 不值得。
**推论**：`PATCH` 不接受 `status` 字段（422），与 `UpdateProjectRequest` 排除 `status` 的形态一致。

### 2.2 `project_contents.current_status` 五值（D-27）

`not_started → learning → reviewing → achieved`，旁路 `waived`。

| 目标态 | 谁能写入 | 说明 |
|---|---|---|
| `not_started` / `learning` / `reviewing` | 用户（`PATCH current_status`） | 允许跳过中间态（`not_started → reviewing`）、允许回退 |
| `waived` | 用户 | 永久放弃；允许从除 `achieved` 外的任何状态进入 |
| `achieved` | **仅 M06 评价结果** | 用户提交 `achieved` → `409`，`message` 明说「掌握结论由评价流程写入」 |

**为什么不照抄 ADR-007**：ADR-007 的统一迁移规则是为「执行动作」（阶段/任务）设计的，`achieved` 在那里的对应物是「完成的动作结果」。而 `achieved` 在本域是**掌握结论**，必须由证据与评价支撑（PRD §7、M06）。若允许用户手点，评价体系立刻失去意义——用户永远可以点一下「已掌握」而不做任何练习。

`achieved_at` 的写入与清空：

| 场景 | `achieved_at` |
|---|---|
| 进入 `achieved` | 写 `now()` |
| 由 M06 撤销 `achieved` → `reviewing` | **保留**（「曾经达成」是事实，与 `reopened_at` 保留同族） |
| 用户从 `learning` 回退到 `not_started` | 不涉及（从未写） |

同态提交（目标态 == 当前态）幂等返回 200，且**不刷新** `updated_at`。

## 3. 资源路径决策

| 资源 | 路径 | 为什么 |
|---|---|---|
| 内容 | `/api/v1/learning-contents` | 内容跨项目复用，**不能**挂在 `/projects/{id}` 下（那会让「一份内容属于一个项目」成为事实标准） |
| 关系 | `/api/v1/learning-contents/{id}/relations` | 关系以源内容为锚点；目标内容只出现在请求体，不构成第二层路径 |
| 标签词表 | `/api/v1/content-tags` | 标签是用户级词表，独立于内容存在（先建标签、后打标） |
| 内容打标 | `/api/v1/learning-contents/{id}/tags` | 关联行挂在内容侧；**整体替换**用 `PUT` |
| 项目内容 | `/api/v1/project-contents` | 关联行有自己的 `id`（关联自身的 `status` / `priority` 可独立更新），因此不是纯嵌套子资源 |

`project-contents` 用顶层路径而非 `/projects/{id}/contents`：该资源既可按项目查（项目详情页），也可按内容查（跨项目复用查询「这份内容在哪些项目里、到哪一步了」，M03 §1 的第四项能力）。挂在项目下会让第二种查询无路径可用。

## 4. 接口总表

### 4.1 内容

| 方法 | 路径 | 要点 |
|---|---|---|
| GET | `/learning-contents` | `content_type` / `status` / `parent_id` / `root_only` / `q` 过滤；分页；排序固定 `updated_at DESC, id DESC`；**不返回 `body`** |
| POST | `/learning-contents` | 创建；响应 `data: { item, similar_hints }`；`similar_hints` 只是提示，**创建必成功** |
| GET | `/learning-contents/{content_id}` | 详情，**唯一返回 `body` 的端点** |
| PATCH | `/learning-contents/{content_id}` | 三态 PATCH（ADR-002）；`status` / `created_source` / `metadata` 不可写（422） |
| DELETE | `/learning-contents/{content_id}` | 默认归档（幂等）；`?purge=true` 物理删除（前置条件见 §6.2） |

过滤参数细节：

| 参数 | 语义 |
|---|---|
| `parent_id` | 传 UUID → 该父节点下的直接子节点；传不了「空」值（query 无法表达 null）→ 用 `root_only=true` 表达「只列根节点」 |
| `root_only` | 与 `parent_id` 互斥，同时给出 → 422 |
| `q` | 标题包含匹配（大小写不敏感）；相似度提示另有专门路径（D-24），本参数只做列表筛选 |
| `status` | 缺省 `active`；`archived` 只返回已归档；`all` 返回两者 |

### 4.2 关系

| 方法 | 路径 | 要点 |
|---|---|---|
| GET | `/learning-contents/{content_id}/relations` | `relation_type` / `direction`（`outbound` / `inbound` / `all`，默认 `all`）；返回 `items` + `total`，**不分页**（单内容关系数上限 200，超出 422） |
| POST | `/learning-contents/{content_id}/relations` | `{target_content_id, relation_type}`；重复边幂等 200；自引用 / 跨用户 / 成环各有独立错误 |
| DELETE | `/learning-contents/{content_id}/relations/{relation_id}` | 物理删；关系不属于该内容 → 404 |

### 4.3 标签

| 方法 | 路径 | 要点 |
|---|---|---|
| GET | `/content-tags` | 分页；`q` 名称包含；排序 `name ASC`（词表要稳定顺序） |
| POST | `/content-tags` | `{name, color?}`；重名 409 |
| PATCH | `/content-tags/{tag_id}` | 改名 / 改色；改名撞已有名 → 409 |
| DELETE | `/content-tags/{tag_id}` | 物理删；关联行由外键 `CASCADE` 清理 |
| GET | `/learning-contents/{content_id}/tags` | 该内容的标签，不分页（单内容标签数上限 20） |
| PUT | `/learning-contents/{content_id}/tags` | 整体替换 `{tag_ids: [...]}`；空数组 = 清空 |

### 4.4 项目内容

| 方法 | 路径 | 要点 |
|---|---|---|
| GET | `/project-contents` | `project_id` 或 `content_id` **二选一必填**（都不传 / 都传 → 422）；分页 |
| POST | `/project-contents` | `{project_id, content_id, target_mastery_level?, priority?, auto_review_enabled?}`；重复关联幂等 200 |
| GET | `/project-contents/{project_content_id}` | 详情 |
| PATCH | `/project-contents/{project_content_id}` | `target_mastery_level` / `priority` / `auto_review_enabled` / `current_status` |
| DELETE | `/project-contents/{project_content_id}` | 解除关联（物理删行） |

创建默认值：`current_status=not_started`、`target_mastery_level=0`、`priority=3`（I3 = 普通，与项目 `importance_level` 默认一致）、`auto_review_enabled=false`、`linked_at=now()`。

## 5. 认证与错误码

所有端点要求 `Bearer JWT`；归属校验一律写进 SQL `WHERE … owner_id = $n`，越权与不存在**同为 404**（防存在性探测，全局规范 §7）。

| 场景 | HTTP / code | 备注 |
|---|---|---|
| 内容 / 项目 / 标签不存在或非本人 | 404 `NOT_FOUND` | 关联创建时「项目不存在」「内容不存在」「不是你的」三者不可区分 |
| 请求体含 `metadata` | 422 `VALIDATION_ERROR` | ADR-009 §3 |
| `body_format` 非法、`source_url` 非 http(s)、超长 | 422 | |
| `parent_id` 成环 / 深度 > 10 | 422 | 深度 10 是技术保护上限，「4–5 层」只是界面建议（M03 §5） |
| `parent_id` 指向他人内容 | 404 | |
| 关系自引用 / 跨用户 / `prerequisite` 成环 | 422 | 跨用户理论上不可达，做防御 |
| 关系重复 | **200 幂等** | `UNIQUE` + `ON CONFLICT DO NOTHING` |
| 标签重名 | 409 `CONFLICT` | 不静默返回既有标签：那会掩盖「同名不同义」的拼写差异 |
| `tag_ids` 含他人标签 | 404 | |
| `tag_ids` 重复 | 422 | |
| 已归档内容加入项目 | 409 | 归档语义 = 不再使用 |
| 用户提交 `current_status=achieved` | 409 | D-27 |
| `purge` 但内容不是 `archived` | 409 | |
| `purge` 但仍有项目关联或子内容 | 409 + `data: {impact, hint}` | `DeletionConflict`（ADR-006 / D-22 明文例外） |
| 列表 `parent_id` 与 `root_only` 同时给出 | 422 | |
| `project-contents` 列表两个过滤参数都缺 / 都给 | 422 | |

## 6. 删除 / 归档策略

### 6.1 分层原则（与 ADR-006 对齐）

| 资源 | 默认动作 | 物理删除 | 理由 |
|---|---|---|---|
| 内容 | 归档 | `?purge=true`，有前置条件 | 用户级资产，被项目引用；误建的内容需要真实退出路径 |
| 内容关系 | 物理删 | — | 关系无历史价值，错了就该消失 |
| 标签 | 物理删 | — | 词表条目，删除即合并；关联行随之消失 |
| 项目内容 | 物理删行 | — | 关联行不是实体，是项目上下文；内容本体保留 |

### 6.2 `purge` 前置条件（三条同时满足）

1. `status = archived`（先归档再彻底删，防误删）；
2. `project_contents` 引用数 = 0；
3. 子内容数 = 0（`parent_id = 该内容` 的记录数）。

任一不满足 → 409 + `data: { impact: { project_contents: N, children: M }, hint: "…" }`。

**不提供 `?cascade=true`**：级联意味着替用户删掉其他项目的学习上下文（`project_contents`），这与 ADR-006「级联只用于 draft 容器」的边界冲突。子内容应由用户先手动上移或归档。

`purge` 的连带清理：`content_relations`（两端）与 `learning_content_tags` 由外键 `ON DELETE CASCADE` 处理；`project_contents` 因前置条件为 0，不会触发。

### 6.3 归档不级联（硬规则）

`DELETE` 归档内容时**不触碰** `project_contents` 与 `content_relations`。项目详情页里那份内容仍显示为「learning / reviewing」，只是不能再新建关联。若改成「归档即从所有项目移除」，用户会失去历史进度且无法撤销。

## 7. 事务边界

| 操作 | 事务 | 说明 |
|---|---|---|
| 内容创建 + 相似提示 | 两条语句，**不要求同一事务** | 提示是只读查询，快照不一致无业务影响 |
| 内容 PATCH（含 `parent_id`） | **单事务** | 改父需在同一事务内做「同 owner + 不成环 + 深度」三项校验，与写入之间不得插入并发写 |
| 关系创建 | **单事务**：锁两端内容行 → 查环 → 插入 | 与 `task_dependencies` 同构（按 id 排序 `FOR UPDATE`，防并发成环） |
| 标签整体替换 | **单事务**：`DELETE` 旧关联 → 校验 `tag_ids` → 批量 `INSERT` | 分两步会在失败时留下空标签集 |
| 项目内容创建 | 单语句 + `ON CONFLICT DO NOTHING` | 归属校验写进 `INSERT … SELECT … WHERE owner` |
| 项目内容 PATCH | 单语句（条件更新带 `WHERE id AND owner`） | 状态机校验在同语句前用 `SELECT … FOR UPDATE` 取当前态 |
| `purge` | **单事务**：校验三条前置 → `DELETE` | 校验与删除之间不得有并发关联 |

- 现状：`modules/knowledge`、`modules/library` 只有空 `mod.rs`，无 DTO、无 handler、无 Migration（`0005` 未编写）。

## 10. 决策记录

### D-23 `content_type` 取值（2026-11-27）

沿用 ERD 三值 `knowledge_point` / `skill_point` / `language_item`，**子类型不入模型**（既不加枚举值，也不放 `metadata`）。ADR-009 §3 已把 `metadata` 在 v1 设为不可写，因此「子类型」这一维度整体延后到有真实需求时再做。

### D-24 相似度提示口径（2026-11-27）

`pg_trgm` 的 `similarity(title, $2) > 0.4`，同 `content_type`、仅 `active`、按分数降序取前 5。**只提示不阻断**（ERD §3.1 明文）。
理由：`similarity()` 对中文按三元组切分，短标题（4–6 字）也能给出可用信号；换成「用户手填是否重复」等于把负担转给用户，换成全文检索则要先建 `tsvector` 与词典配置，成本高于收益。

> **实现期实测（2026-11-28）**：`similarity('极限的定义','极限定义') = 0.375`（**低于** 0.4）、`similarity('极限的定义','极限的定义(修订)') = 0.667`。4–6 字中文短标题的相似度确实偏低，阈值按本决策**保持 0.4 不动**，集成测试改用后者验证提示通路。若后续「一字之差漏报」影响实际使用，调阈值属于下表中 M11 的「相似度阈值调优」范围。

### D-25 关系方向（2026-11-27）

单向存储、双向查询。`prerequisite` / `contains` / `extends` 方向由语义决定（A 是 B 的前置 → 一行 `A --prerequisite--> B`）；`related` / `alternative` 语义对称，但**仍只存一行**，查询时按 `(source = id OR target = id)` 展开并标注 `direction`。
理由：存两行会让「删除一条关系」变成「删除两条」，且两行可能不同步；对称性在查询层展开的成本只是一次 `OR`。

### D-26 内容删除语义（2026-11-27）

`DELETE` = 归档（幂等，不动项目上下文与关系）；`?purge=true` = 物理删除，需「已归档 + 无项目关联 + 无子内容」三条前置，不提供级联。
理由：内容是被项目引用的用户级资产（ADR-006 的第三层），不能像 draft 容器那样级联；但误建内容必须有退出路径，否则会把错误数据永久留在列表里。

### D-27 `project_contents.current_status` 迁移（2026-11-27）

用户可写 `not_started` / `learning` / `reviewing` / `waived`，允许跳过中间态与回退；`achieved` **只能由 M06 写入**，用户提交即 409；离开 `achieved` 时保留 `achieved_at`。
理由见 §2.2。这条与 ADR-007 的差异是**刻意的**：ADR-007 管「动作型状态」，这里是「结论型状态」。

### D-28 标签契约形态（2026-11-27）

词表 CRUD 独立成 `/content-tags`；内容侧打标用 `PUT` 整体替换，不做 `POST`/`DELETE` 逐条增删。重名返回 409。
理由：整体替换是幂等操作，前端一次提交多选结果即可，不需要维护「哪些加了、哪些删了」的差集；重名 409 而非静默合并，是为了不让「同名不同义」被无声吞掉。

### D-29 正文模型（2026-11-27）

确认 **ADR-009**：`body` + `body_format`（`markdown` / `plain_text`）+ `source_url`；`metadata` v1 不读写；附件不入内容域；后端不渲染不净化。
