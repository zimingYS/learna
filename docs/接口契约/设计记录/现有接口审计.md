# 现有接口审计

**状态：** 已完成（2026-11-27）  
**范围：** 后端全部路由、DTO、响应信封、错误码与前端请求封装，对照 PRD V1.0 / ERD V1.0 / TAD V1.0 / 数据库与API规则  
**目的：** 确认「现状实现」与「正式领域模型」的差异，为接口契约分层定稿提供依据。本文只陈述事实与差异，不擅自改写业务规则。

> ⚠ **时效提示（2026-11-28）**：本文是 2026-11-27 的**审计快照**，记录的是当时的事实。
> 其中的过渡 `/api/v1/records` 与 `learning_records` 表已于 2026-11-28 下线
> （迁移 `0007` 导数据、`0008` 删表，模块与路由已移除）。差异分析仍有效，
> 但「现状」一节描述的表与端点不再存在——当前状态见 `接口清单.md` §3 / §4.3 与 ADR-010 §6。

## 1. 现状端点清单（本轮修订后）

| 方法 | 路径 | 认证 | 说明 |
|---|---|---|---|
| GET | `/healthz` | 无 | 存活探针（基础设施端点，不版本化） |
| GET | `/readyz` | 无 | 就绪探针（`SELECT 1`） |
| POST | `/api/v1/auth/register` | 无 | 注册，返回 JWT + 用户信息 |
| POST | `/api/v1/auth/login` | 无 | 登录，返回 JWT + 用户信息 |
| GET | `/api/v1/records` | JWT | 分页列表（`created_at DESC`） |
| POST | `/api/v1/records` | JWT | 创建记录 |
| GET | `/api/v1/records/{id}` | JWT | 详情（越权按 404） |
| PATCH | `/api/v1/records/{id}` | JWT | 部分更新（本轮由 PUT 改为 PATCH） |
| DELETE | `/api/v1/records/{id}` | JWT | 物理删除 |

### 1.1 现状 DTO（学习记录）

- `CreateRecordRequest`：`title`（必填）、`content?`、`duration_minutes?`、`subject?`
- `UpdateRecordRequest`：全部字段可选
- `RecordResponse`：`id, title, content, duration_minutes, subject, created_at, updated_at`
- `RecordListResponse`：`{ items, total }`；查询参数 `page`（≥1，默认 1）、`page_size`（1–100，默认 10）
- 数据库表 `learning_records`：`id UUID / user_id UUID FK→users CASCADE / title TEXT NOT NULL / content TEXT / duration_minutes INT4 NOT NULL DEFAULT 0 / subject TEXT / created_at / updated_at`

### 1.2 现状认证与隔离

- JWT（HS256，`sub` = 用户 UUID 字符串，有效期 7 天），`Authorization: Bearer <token>`
- 所有 `/records` 查询均带 `user_id` 过滤；访问他人资源返回 `NOT_FOUND`（404），不暴露资源存在性

## 2. 与正式领域模型的差异对照（LearningRecord vs LearningSession）

依据：ERD V1.0 §5.3 `LearningSession`、§3.3 计量规则（D-03）、§8 删除策略。**现状 `learning_records` 是已确认的过渡接口，不得直接充当正式 LearningSession 契约。**

| 维度 | 现状 `learning_records` | 正式 `LearningSession`（ERD） | 差异性质 |
|---|---|---|---|
| 归属字段 | `user_id` | `owner_id` | 命名差异 |
| 主项目 | 无 | `primary_project_id`（可空，唯一计量归属） | 缺字段（D-03 计量规则无法表达） |
| 标题 | `title` NOT NULL | `title` NULL | 约束差异 |
| 活动类型 | 无 | `activity_type`（theory/practice/review/mixed/other） | 缺字段 |
| 发生时间 | 无 | `started_at` / `ended_at` NOT NULL，`ended_at >= started_at` | 缺字段 |
| 时长来源 | `duration_minutes` 由请求方提供 | 由服务端按时间区间或用户确认的有效时长生成 | 语义差异（前端信任 vs 服务端生成） |
| 内容描述 | `content`（单字段自由文本） | `summary / what_done / problems / next_steps` 四字段 | 结构差异 |
| `subject` | 自由文本字段 | 无对应字段（知识归属由 `SessionContent` 关联表达） | 模型外字段 |
| 关联关系 | 无 | `SessionContent` / `SessionProject` / `TaskSession` / `LearningEvidence` | 缺关系 |
| 来源标记 | 无 | `created_source`（user/timer/imported） | 缺字段 |
| 删除语义 | 物理删除 | 保留历史，更正需审计（ERD §8） | 语义差异 |
| 审计 | 无 | 主项目归属调整需变更审计 | 缺能力 |

**结论：** 差异覆盖字段、约束、计量语义、关联与删除策略五个层面。正式 LearningSession 契约应在 P1 模块设计时逐字段确定并单独评审；映射关系（如 `content` 是否拆分为四字段、`subject` 去留）属未确定事项，见 §5。

## 3. 统一响应审计（两项要求 + 附带发现）

### 3.1 错误响应缺少 request_id — **已修复（本轮）**

- 原状：`AppError: IntoResponse` 构造 `ApiResponse::error` 时 `request_id` 恒为空字符串；仅成功路径手动 `.with_request_id(...)`。
- 修复：
  - 移除 `AppError` 的 `IntoResponse` 实现，新增 `into_response_with_request_id(self, request_id)`；
  - 处理器统一返回 `ApiReply<T>(AppResult<T>, RequestId)`，成功与失败都走真实 request_id；
  - `auth_middleware` 错误路径同样从扩展读取 request_id 注入。
- 效果：编译期杜绝「错误响应空 request_id」的路径（`AppError` 不能再被框架自动转响应）。

### 3.2 PUT 与部分更新语义错位 — **已修复（本轮）**

- 原状：`PUT /records/{id}` 携带全可选 DTO，实际是部分更新语义，与 PUT 全量替换语义不符。
- 修复：改为 `PATCH /records/{id}`（与 TAD §6.1「PATCH 明确区分字段缺失、显式 null 和具体值」一致）；PUT 保留给未来的全量替换场景。前端 api 封装与集成测试已同步。

### 3.3 附带发现

| # | 发现 | 处置 |
|---|---|---|
| 1 | 信封 `code` 为字符串 `"200"`，TAD §6.2 示例为数字 `200` | 保留字符串：TAD §6.2 原文「可延续项目现有统一响应信封方向」，示例非冻结规范；前后端已按字符串实现，避免无收益破坏性变更 |
| 2 | 请求体/查询串解析失败（extractor 拒绝）由框架默认响应处理，不经统一信封、无 request_id | **待决策**：是否自定义 rejection 映射进统一信封 |
| 3 | `duration_minutes` 列为 `NOT NULL DEFAULT 0`，响应 DTO 却为 `Option<i32>` | 记录在案；形态随正式 LearningSession 契约统一 |
| 4 | PATCH 过渡接口当前为「二态」：字段缺失与显式 `null` 均视为不修改（`content` 无法置回 NULL） | **待决策**：是否升级 `Option<Option<T>>` 三态，或保持二态直至正式契约落地 |

## 4. 其他审计结论

- **认证链路**：注册/登录免认证，其余业务接口走 JWT 中间件；前端 401 拦截器按相对 URL 识别登录/注册接口，版本前缀变更不影响其判定。
- **数据隔离**：`user_id` 过滤 + 越权 404，符合「后端必须对每个用户资源执行所有权校验」（PRD §16.1）。
- **分页**：`page / page_size` + `total`，排序固定 `created_at DESC`（后端决定，未开放排序参数）。
- **错误码**：`VALIDATION_ERROR / UNAUTHORIZED / FORBIDDEN / NOT_FOUND / CONFLICT / RATE_LIMITED / UPSTREAM_ERROR / INTERNAL_ERROR / HASH_ERROR / TOKEN_ERROR`，与 HTTP 状态码映射稳定（见全局规范）。
- **`UserResponse::from_row(id: i64)`**：与 UUID 主键不匹配的遗留辅助函数，service 实际走 `id::text`；建议下轮清理，不影响契约。

## 5. 未决事项（待决策，等待项目负责人确认）

1. 过渡 `/records` 是否升级 PATCH 三态（`Option<Option<T>>` 区分缺失/null/值），还是保持二态直至正式 LearningSession 落地。
2. 正式 LearningSession 契约的字段映射：`content` 是否拆为 `summary/what_done/problems/next_steps`；`subject` 的去留。
3. 学习时长生成规则（ERD §12.4 计时规则未锁定：暂停、跨午夜、补录、有效时长修正）。
4. 删除语义：物理删除 vs 软删除/保留审计（ERD §8 规定 LearningSession 保留）。
5. extractor 拒绝响应是否纳入统一信封（含 request_id）。
6. 创建成功返回 201 还是维持 200（现状 200 + 信封携带 id）。
7. 正式资源路径最终冻结（TAD §11 明确完整 API URL 暂不冻结）。
8. 分页排序参数与 cursor 分页演进策略。
9. OpenAPI 契约的 CI 校验接入方式（TAD §6.1 要求纳入 CI）。
