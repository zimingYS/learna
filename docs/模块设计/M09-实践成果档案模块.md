# M09 实践成果档案模块

**契约状态：** §4.5 `/artifacts` ⬜ 规划中，无 DTO、无 openapi 条目
**实现状态：** ⬜ 目录不存在（需新建 `modules/artifact`）
**依据：** PRD §10（实践学习与成果档案）、§18 第 11 项（附件规格未定）；TAD §3.8（`Artifact` / `ArtifactContentRelation`）；ERD **无本域表定义**

## 1. 职责与边界

**做什么**：

| 能力 | 状态 |
|---|---|
| 成果档案：链接（Git 仓库 / Commit / PR）、附件、说明文字 | ❓ 未设计 |
| 成果类型化（代码 / 文档 / 设计 / 录音 / 写作文本 / 截图） | ❓ |
| 成果关联多个技能点（`ArtifactContentRelation`） | ❓ |
| 成果关联项目 / 阶段 / 里程碑 | ❓ |
| 「关键阶段必须提供成果」的校验 | ❓（无落地路径，见 §5） |

**不做什么**（这些属其他模块，勿塞进本域）：

| 不做 | 归属 | 理由 |
|---|---|---|
| **实践过程记录**（做了什么、遇到什么问题、怎么解决） | M05 `LearningSession`（`activity_type = practice`） | 见下方核心判断 |
| 实践能力评价（技能类 L0–L4） | M06 | 成果是技能类评价的重要证据，评价本身归 M06 |
| 学习证据（一次活动的附件） | M05 `learning_evidence` | 证据服务于「这次学了什么」，成果服务于「我产出了什么」 |
| 文件存储实现 | 横切 `infrastructure/storage` | 本域只用 `storage_key`；`LocalStorage` 是 stub |
| 内容本体 | M03 | 技能点来自 `learning_contents`（`content_type = skill_point`） |

**核心判断：PRD §10 的标题是「实践学习与成果档案」，但它其实是两件事**：

| 关注点 | PRD 条款 | 归属 | 数据形态 |
|---|---|---|---|
| **过程**：实际做了什么、用了什么技术、遇到什么问题、如何解决 | §10.1 | M05 | `LearningSession` 的四段式字段（`what_done` / `problems` / `next_steps` / `summary`） |
| **产物**：Git 链接、截图、文档、录音、作品 | §10.2 | **本模块** | `Artifact` + 关联行 |

把两者混成一个模块会导致一个尴尬问题：一次实践可能没有产物（学习了但没做出东西），一个产物可能来自多次实践（迭代了三天才提交）。**过程是时间轴上的点，产物是独立的实体**，它们的基数是 N:M，不能塞进一张表。

**为什么成果要独立实体而不是给 session 加附件**：`learning_evidence` 已经存在（M05），它挂 `session_id`。若成果也走证据，会出现「三个月前那个 commit 是哪次 session 的？」——答案往往是「不知道，我提交时没记」。成果必须有独立的归属（项目 + 技能点），不依赖某次会话。

## 2. 目录与文件形态

```text
modules/artifact/             ⬜ 待建
├── mod.rs
├── dto.rs                    # ArtifactItem / CreateArtifactRequest / UpdateArtifactRequest
│                             # ArtifactContentLink / ArtifactAttachment
├── handler.rs                # 成果 CRUD、技能点关联、附件上传
├── service.rs                # 成果 CRUD + 关联校验
├── rules.rs                  # 纯函数：成果类型与必填字段的匹配（链接类 vs 附件类）
└── link.rs                   # 外部链接校验（Git URL 形态、可达性可选）
```

**`link.rs` 是否值得单独一文件**：取决于是否做链接可达性检测。Git 仓库链接的形态校验（`https://github.com/…`、`git@…`、`ssh://…`）本身是纯函数，可单测；可达性检测是外部 HTTP，**不能进事务**（`README.md` §6.3）。若不做可达性，`link.rs` 可并入 `rules.rs`。

## 4. 调用链与分层

**创建成果（含附件）**：

```text
POST /api/v1/artifacts
  → service::create(&db, user_id, req)
      1. 校验 project_id 属当前用户
           SELECT id FROM learning_projects WHERE id = $1 AND owner_id = $2
           -- 无行 → NotFound
      2. 校验 artifact_type 与字段组合（rules::validate_shape）
           - 链接类（code_repo / commit / pr）→ external_url 必填
           - 附件类（document / image / audio / design）→ 需后续上传附件（可先建后传）
           - 两类可共存
      3. INSERT INTO artifacts (…) RETURNING …
    → ApiReply(Ok(ArtifactItem), req_id)

POST /api/v1/artifacts/{id}/attachments   (multipart)
  1. 校验成果归属 + 附件规格
  2. **事务外**上传对象存储 → storage_key
  3. 事务内 INSERT INTO artifact_assets (artifact_id, storage_key, mime_type, size_bytes)
  4. 若第 3 步失败 → 孤儿对象（需清理任务或改预签名直传）
```

**为什么附件上传不能进事务**：对象存储是外部服务，长事务会持锁数十秒（`README.md` §6.3）。正确形态是「先上传、再登记」，并接受短窗口的孤儿对象。

## 5. 数据与不变量

**V1.2 已建 4 张表（ERD §5.8）**：

| TAD 实体 | ERD V1.2 表 | 决策 |
|---|---|---|
| `Artifact` | `artifacts` | `project_id NOT NULL`；`artifact_type` 七值由 V1.2 首次给出；**不设 `external_url`** |
| （TAD 单个 `asset_id`） | `artifact_assets` | 拆成复数表：`asset_role` 六值 + `storage_key` + 元数据 |
| （TAD 只有 `external_url`） | `artifact_links` | `link_type` 五值：`git_repo` / `commit` / `pull_request` / `demo` / `other` |
| `ArtifactContentRelation` | `artifact_content_relations` | 复合主键 + `contribution`（`primary` / `supporting`），与 `GoalStage` 共用同一枚举 |

三处取舍：

1. **成果必须归属项目**：PRD §10 把成果放在实践语境，TAD 也只给 `project_id`。若将来要「个人成果档案」，需改为可空并引入归属枚举——属模型变更，见 ERD §12 第 14 项。
2. **附件是复数**：PRD §10.2「运行截图、图片和文档」；TAD 的单 `asset_id` 不够用。
3. **不设 `external_url` 单值**：外部链接统一走 `artifact_links`，否则会出现「一个链接在 artifact 表、另一个在 links 表」的两处真相。

**一处不是本模块能修的**：PRD §10.2「关键阶段目标可以设置必须提供成果证据」需要把「阶段完成条件」与成果连起来，但阶段完成条件走 `stages.completion_rule`，而 D-08 已决策该字段不进契约、DB 恒 null（ADR-007）。所以这条需求**当前没有存储与校验路径**，需等「完成条件」专项或 AI 线设计。**不要**为此在 `artifacts` 加 `is_required`——需求是「阶段要求成果」，不是「成果要求自己」。

**必须保证的不变量（PRD 明文）**：

| 不变量 | 依据 |
|---|---|
| 成果附件**默认可选**，不强制每次实践都上传 | PRD §10.2「成果附件默认可选」 |
| 关键阶段目标**可以**设置必须提供成果证据 | PRD §10.2（但见下方阻塞） |
| 成果必须属于某项目（或允许「无项目成果」？需决策） | TAD `Artifact.project_id`；PRD §10 未明确能否游离 |
| 关联的技能点必须与成果同属一个 owner | 跨表 |

**一处必须指出的落地缺口**：PRD §10.2「关键阶段目标可以设置必须提供成果证据」需要把「阶段完成条件」与「成果」连起来。但：

1. 阶段完成条件字段是 `stages.completion_rule`（JSONB）；
2. **D-08 已决策：`completion_rule` 不进契约**，DTO 不出现该字段、DB 列恒为 null（ADR-007 §2）；
3. 因此「必须提供成果」这个条件**当前没有任何存储与校验路径**。

这不是本模块能解决的，需要在 AI 线或「完成条件」专项设计时一并处理。**不要**为了让这条需求落地而在 `artifacts` 表加一个 `is_required` 字段——需求是「阶段要求成果」，不是「成果自己要求自己」。

## 6. 状态与副作用

**无状态机**。成果是静态产物，删除即删除。

**副作用**：

| 动作 | 写入 |
|---|---|
| 创建成果 | `artifacts` 行；`created_at` |
| 上传附件 | `artifact_assets` 行 + 对象存储对象（**两步，不可原子**） |
| 关联技能点 | `artifact_content_relations` 行（整体替换语义） |
| 删除成果 | 删关联行 + 删附件行 + **删对象存储对象**（第三步不可回滚，顺序应为「先删 DB 后删对象」，失败时留孤儿对象而非悬空 key） |
| 删除单个附件 | 同上，单条 |

**删除顺序的理由**：若先删对象再删 DB，第二步失败会留下「DB 有记录但文件已没了」的悬空引用（用户点开 404，且无法修复）。反之留下孤儿对象只是浪费空间，可定期清理。**能容忍的失败方向要选对**。

| 场景 | 变体 | HTTP | 备注 |
|---|---|---|---|
| 成果不存在 / 非本人 | `NotFound` | 404 | |
| 项目不存在 / 非本人 | `NotFound` | 404 | |
| `artifact_type` 与字段组合不符（如 `code_repo` 无 `external_url`） | `Validation` | 422 | |
| 链接格式非法 | `Validation` | 422 | 只校验形态，不校验可达性 |
| 附件过大 / 格式不支持 | `Validation` | 422 | 阈值待决策 3 |
| 关联的技能点跨用户 | `Validation` | 422 | |
| `LocalStorage` 未实现 | `Internal` | 500 | 当前上传即 500，见 §10 |

## 8. 事务边界

| 操作 | 事务 |
|---|---|
| 创建 / 更新成果（无附件） | 单语句 |
| 上传附件 | **外部上传不进事务**：先上传 → 再单事务登记 |
| 关联技能点整体替换 | 单事务：删旧 → 校验新 → 插入 |
| 删除成果 | 单事务删 DB（关联 + 附件行 + 主行）→ **事务外**删对象存储 |
| 删除单个附件 | 单语句删行 → 事务外删对象 |
