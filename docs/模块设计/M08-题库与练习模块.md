# M08 题库与练习模块

**契约状态：** §4.4 的 `/questions`、`/practice-sessions` ❓ 未设计
**实现状态：** ⬜ 目录不存在（需新建 `modules/question`、`modules/practice`）
**依据：** PRD §9（题库与练习系统）、§18 第 10/11 项（AI 生成题校验、图片规格未定）；TAD §3.7（10 个建议实体 + 图片与 OCR）；ERD §12 第 2 项（**完整模型明确未锁定**）

## 1. 职责与边界

**做什么**：

| 能力 | 状态 |
|---|---|
| 多题型题目管理（9 类：单选/多选/判断/填空/简答/计算/编程/主观论述/英语作文翻译） | ❓ 模型未锁定 |
| 题目版本（`QuestionVersion`）—— 题干修订不破坏历史作答 | ❓ |
| 练习会话（`PracticeSession` + `PracticeAnswer`） | ❓ |
| 六种练习模式：知识点专项 / 随机 / 错题重练 / 自定义 / 题组 / 限时测试 | ❓ |
| 判分：客观自动、主观自评、AI 辅助评价（须标明） | ❓ |
| 错题本与错题状态（`WrongQuestionState`） | ❓ |
| AI 生成题目的四态审核（`draft / pending_review / approved / rejected`） | ❓ |
| 拍照录题：原图 + 压缩副本 + OCR 文本 + 用户修订（两者分开保存） | ❓ |

**不做什么**（这些属其他模块，勿塞进本域）：

| 不做 | 归属 | 理由 |
|---|---|---|
| 知识点本体 | M03 | `QuestionKnowledgePoint` 是多对多关联，内容归 M03 |
| 复习排期 | M07 | 错题进复习队列由 M07 管；本域只提供「这题错了」的事实 |
| 掌握度等级 | M06 | 正确率是评价**输入**，本域不算等级 |
| 学习活动 | M05 | 练习可产生 `LearningSession`（`activity_type=practice`），但 session 归 M05 |
| 文件存储实现 | 横切 `infrastructure/storage` | 本域只用 `storage_key`；`LocalStorage` 仍是 stub |

**核心判断：为什么题库要独立成模块，且必须是全新模型**：

ERD §12 第 2 项把「错题与题库的完整领域模型」列为**未锁定**，并明确要「单独评审」。这不是懒，是因为题型差异太大：单选题的答案是 `{option_id}`，编程题是「代码 + 测试用例结果」，英语作文是「文本 + 评分维度」。**用一张表存所有题型，必然退化成一堆可空字段加一个 JSONB 黑盒**。

TAD §3.7 给的正确方向是「题目类型应使用可扩展类型标识，不同题型的答案结构应由类型化 DTO/JSON Schema 约束，避免把所有题目硬编码成单一文本字段」。这意味着本模块的设计成本主要在**题型建模**，不在 CRUD。

## 2. 目录与文件形态

```text
modules/question/             ⬜ 待建
├── mod.rs
├── dto.rs                    # QuestionDto / QuestionVersionDto / QuestionSetDto
├── handler.rs                # 题目 CRUD、版本、审核、题组
├── service.rs                # 题目 CRUD + 版本管理 + 审核流转
├── grading.rs                # 判分规则（客观题按题型分派）
├── ocr.rs                    # 拍照录题：上传、压缩、OCR、校对合并
└── types/                    # 题型专属的答案结构（每类一个模块）
    ├── choice.rs             # 单选 / 多选
    ├── blank.rs              # 填空
    ├── subjective.rs         # 简答 / 计算 / 论述 / 作文翻译
    └── code.rs               # 编程题（含测试用例）

modules/practice/             ⬜ 待建
├── mod.rs
├── dto.rs                    # PracticeSessionDto / SubmitAnswerRequest / PracticeResultDto
├── handler.rs                # 开始练习、提交单题、交卷、查结果
├── service.rs                # 会话编排、题目抽取（模式）、判分落库
└── selector.rs               # 抽题策略（专项/随机/错题/自定义/题组/限时）
```

**为什么按题型拆 `types/` 而不是一个大 enum**：9 类题型的答案结构与判分逻辑都不同，塞在一个文件里会变成 800 行的 `match`。按题型分文件后，`grading.rs` 只做分派（`match question_type { Choice => choice::grade(...), … }`），新增题型只加一个文件 + 一个分支。

## 4. 调用链与分层

**开始一次专项练习**：

```text
POST /api/v1/practice-sessions
  { mode: "knowledge_point", content_ids: [...], question_count: 20, time_limit_minutes: null }
  → service::start(&db, user_id, req)
      1. 校验 content_ids 全部属当前用户
      2. selector::pick(&db, mode, filters) → Vec<QuestionId>
            SELECT id FROM questions
             WHERE owner_id = $1
               AND status = 'approved'          -- 只从已审核题库抽题
               AND id IN (SELECT question_id FROM question_knowledge_points WHERE content_id = ANY($2))
             ORDER BY random() LIMIT $3
      3. INSERT INTO practice_sessions (…) RETURNING …
      4. INSERT INTO practice_answers (session_id, question_id, position)  -- 预置空作答行
    → 返回 session + 题目列表（**不含答案**）
```

**提交单题作答（客观题）**：

```text
POST /api/v1/practice-sessions/{sid}/answers
  { question_id, answer: {...} }
  → service::answer(&db, user_id, sid, req)
      1. SELECT pa.*, q.question_type, q.answer_key, q.status
           FROM practice_answers pa JOIN questions q ON q.id = pa.question_id
          WHERE pa.session_id = $1 AND pa.question_id = $2
            AND EXISTS (SELECT 1 FROM practice_sessions s WHERE s.id = $1 AND s.owner_id = $3)
          FOR UPDATE                                  -- 锁作答行，防重复提交
      2. grading::grade(question_type, answer_key, submitted)  -- 纯函数分派
      3. UPDATE practice_answers SET answer=…, is_correct=…, score=…, graded_at=now()
      4. 若错 → UPSERT wrong_questions（每题一行，累加 error_count）
      5. 若题目 status != 'approved' → **不写** resulting_level（见 §6）
```

**关键设计：答案绝不下发**。列表与详情返回题目时必须剥离 `answer_key`，否则用户 F12 就能看答案。判分只在服务端做，客户端只拿到「对/错 + 解析」。

**拍照录题的流水线**：

```text
POST /api/v1/questions (multipart: image + optional ocr_text)
  1. 校验图片（格式、大小）→ 压缩副本
  2. 事务外上传：原图 → storage_key_original，压缩图 → storage_key_compressed
  3. OCR（可选，失败不阻断）→ ocr_text + ocr_confidence + ocr_status
  4. 事务内落库：question（status=draft, source=image_ocr）
       + question_assets（original_asset_id, compressed_asset_id）
       + ocr_result（raw_text, confidence, version）
  5. 用户校对后 PATCH → 写 `revised_content`，**不覆盖** `ocr_result.raw_text`
```

PRD §9.5 的三条硬要求：原图保留（除非用户主动删）、过大图片压缩但保留可读性、**OCR 失败仍允许仅凭原图保存和练习**。第三条决定了 OCR 必须是**可选步骤**，不能作为创建题目的前置条件。

## 5. 数据与不变量

**ERD 完全没有本域的表**。TAD §3.7 给了 10 个建议实体，但无字段级定义：

| 实体（TAD） | 职责 | 字段状态 |
|---|---|---|
| `Question` | 题目主表（类型、来源、审核状态） | 未定义 |
| `QuestionVersion` | 题干/答案的历史版本 | 未定义 |
| `QuestionOption` | 选项（选择题专用） | 未定义 |
| `QuestionAsset` | 题目图片（原图 / 压缩副本） | 未定义 |
| `QuestionKnowledgePoint` | 题目-知识点多对多 | 未定义 |
| `QuestionSet` | 题组 | 未定义 |
| `PracticeSession` | 一次练习 | 未定义 |
| `PracticeAnswer` | 单题作答 | 未定义 |
| `WrongQuestionState` | 错题状态（错误次数、已掌握） | 未定义 |
| `QuestionReviewHistory` | 题目审核历史 | 未定义 |

**唯一已定的枚举（TAD §3.7）**：

- 题目来源：`user_created / ai_generated / imported / image_ocr`
- 审核状态：`draft / pending_review / approved / rejected`

**必须保证的不变量（PRD 明文，与表结构无关）**：

| 不变量 | 依据 |
|---|---|
| **未 `approved` 的题目不得进入正式掌握统计** | PRD §9.4；TAD §3.7 |
| AI 生成的题目必须经内容、答案、解析校验并由用户确认后才能进正式题库 | PRD §9.4 |
| 未确认题目可作为**临时练习**，但不计入统计 | PRD §9.4 |
| 客观题自动判分、主观题允许自评、**AI 评分必须标明为辅助结果**不得伪装成权威判分 | PRD §9.3 |
| 用户可以修改最终作答评价 | PRD §9.3 |
| 原图保留；OCR 结果与用户修订**分别保存** | PRD §9.5；TAD §3.7 |

**「AI 评分必须标明辅助」的实现约束**：`PracticeAnswer` 需要一个字段区分「谁判的」——`graded_by`（`auto` / `self` / `ai_assisted` / `user_corrected`）。若只有 `score`，前端无法区分「AI 给的 3 分」与「我给的 3 分」，PRD §9.3 的要求就落空了。

## 6. 状态与副作用

**题目审核状态机**：

| 当前 | 动作 | 目标 | 副作用 |
|---|---|---|---|
| （无） | 用户手建 | `draft` | — |
| （无） | AI 生成 | `pending_review` | `source = ai_generated`；必须带 `ai_model` 与生成时间 |
| （无） | 拍照录入 | `draft` | `source = image_ocr` |
| （无） | 用户手建并直接使用 | `approved` | 用户自建可跳过审核 |
| `draft` | 提交审核 | `pending_review` | — |
| `pending_review` | approve | `approved` | 写入 `reviewed_at`；此后可进正式题库与统计 |
| `pending_review` | reject | `rejected` | 保留理由；不可再 approve（需重新生成） |
| `draft` / `pending_review` | 直接用于临时练习 | 状态不变 | **允许**，但不写统计 |

**练习会话状态**：`in_progress → submitted`（交卷）或 `abandoned`（超时 / 用户退出）。限时测试超时由服务端判定（`started_at + time_limit < now()`），**不能只靠前端倒计时**。

**副作用**：

| 动作 | 写入 |
|---|---|
| 提交作答（客观题） | `practice_answers`：`answer` / `is_correct` / `score` / `graded_by=auto` / `graded_at` |
| 答错 | `wrong_questions` UPSERT：`error_count += 1`、`last_wrong_at = now()` |
| 提交作答（主观题） | `score = NULL`，等自评或 AI 辅助；`graded_by` 先留空 |
| 用户自评 | `score` / `graded_by=self`；可覆盖 AI 的值（`graded_by=user_corrected`） |
| 交卷 | `practice_sessions.submitted_at`；汇总正确率 |
| 题目修订 | 新建 `QuestionVersion`；旧版本保留，历史作答仍指向旧版本 |

**跨模块副作用（唯一的）**：练习结果可作为 M06 的系统评价输入，但**不直接写 `mastery_assessments`**。M06 读取练习统计后自行决定是否生成建议——保持「评价的判定权在 M06」这一边界。

## 7. 错误映射

| 场景 | 变体 | HTTP | 备注 |
|---|---|---|---|
| 题目 / 会话不存在或非本人 | `NotFound` | 404 | |
| 向已交卷的会话提交作答 | `Conflict` | 409 | |
| 重复提交同一题（同一会话） | `Conflict` | 409 | 或幂等覆盖（需决策） |
| 作答结构与题型不符（如单选传数组） | `Validation` | 422 | 题型 DTO 校验 |
| 主观题提交 `score` | `Validation` | 422 | 主观题由判分流程写，不接受客户端直传 |
| 抽题结果为空（筛选条件太窄） | `Validation` | 422 | 提示「该知识点下无已审核题目」 |
| 图片过大 / 格式不支持 | `Validation` | 422 | 阈值待决策 8 |
| 对 `rejected` 题 approve | `Conflict` | 409 | |
| `LocalStorage` 未实现 | `Internal` | 500 | 当前调用即 500，见 §10 |

## 8. 事务边界

| 操作 | 事务 |
|---|---|
| 题目创建（无图片） | 单语句 |
| 题目创建（含图片） | **外部上传不进事务**：先上传对象 → 再单事务写入 `question` + `question_assets` + `ocr_result` |
| 题目修订 | 单事务：插 `QuestionVersion` + 更新 `Question.current_version_id` |
| 审核 | 单事务：更新 `status` + 插 `QuestionReviewHistory` |
| 开始练习 | 单事务：插 `practice_sessions` + 批量插 `practice_answers`（预置行） |
| 提交作答 | 单事务：更新作答行 + UPSERT 错题行 |
| 交卷 | 单事务：更新 session + 汇总统计 |

**图片上传的孤儿问题**：上传成功但事务失败会产生无主对象。处置：定期清理「存储中无 DB 引用」的对象，或改用预签名 URL 让客户端直传后再登记（更复杂但无孤儿）。

## 9. 测试策略

待建 `backend/tests/question_flow.rs` + `practice_flow.rs`：

| 用例组 | 断言 |
|---|---|
| 题目 CRUD | 各题型创建与回显；题型与答案结构不匹配 → 422 |
| 审核流 | AI 生成 → `pending_review`；approve 后可抽到；reject 后抽不到 |
| 版本化 | 修订后旧作答仍指向旧版本；新旧版本内容不同 |
| 抽题 | 专项模式只抽该知识点的 `approved` 题；随机模式不重复；题组模式按顺序 |
| 判分 | 单选/多选/判断/填空的自动判分正确；多选漏选按规则扣分（规则需决策） |
| 主观题 | 提交不写 `score`；自评写入 `graded_by=self`；AI 辅助写入 `graded_by=ai_assisted` |
| **统计隔离** | 用 `draft` 题练习 → 正确率有记录但 **`resulting_level` 为空**、M06 无新评价 |
| 错题 | 答错 → `error_count=1`；再错 → 2；答对不自动清零（需决策 6） |
| 限时 | 超时后提交 → 409；超时后查询 → `abandoned` |
| 图片 | 上传后两个 key 非空；OCR 失败仍创建成功且 `ocr_status=failed`；校对后 `raw_text` 未被覆盖 |

单测落 `grading.rs` 与 `types/*`：每类题型的判分边界（空答案、多答案、大小写、空格、数值容差）。

## 10. 实现状态与缺口

**已实现**：无。ERD 无表，代码无目录。

**阻塞项（前两项是硬阻塞，且都属「需要单独评审」级别）**：

| # | 阻塞 | 说明 |
|---|---|---|
| 1 | **完整领域模型未锁定** | ERD §12 第 2 项明确「Question、QuestionVersion、Attempt、WrongAnswer、QuestionContent 等」需单独评审。10 个实体、9 种题型，这是一次独立的建模工作，不是补几列 |

| 4 | **图片规格未定**（PRD §18 第 11 项） | 无法做上传校验 |
| 5 | **OCR 提供方未定** | 本地模型需额外部署，云 API 需密钥管理与成本控制 |

**建议的实现策略**：本模块是 **P2 中风险最高、投入最大**的一块。不建议与 M06/M07 并行开工。

最小可用切片的建议顺序：

1. **只做单选 + 判断题**（答案结构最简单：`{option_id}` / `{bool}`），题目 CRUD + 手动建题 + 专项练习 + 自动判分。不碰 AI、不碰 OCR、不碰版本化。
2. 加多选题、填空题（引入 `answer_key` 的结构化数组）。
3. 加错题本（需要决策 6）。
4. 加主观题与自评（引入 `graded_by`）。
5. 最后做 AI 生成 + 审核流 + 拍照录题（依赖 M12 与存储层）。

**一个必须避免的陷阱**：不要在没有审核流的情况下就让 AI 生成题进题库。PRD §9.4 的要求是「未确认题目可以作为临时练习，但不能进入正式掌握度统计」——如果 `approved` 这个字段一开始不存在，后面要补就得迁就历史数据，且已经产生的掌握统计无法回溯剔除。
