# M03 学习内容管理模块

**契约状态：** §4.2 两组资源 ⬜ 规划中，**无 DTO、无 openapi 条目**
**实现状态：** 🟡 `modules/knowledge`、`modules/library` 只有空 `mod.rs`
**依据：** PRD §6（学习内容体系）；ERD §3.1（允许重复、提供复用提示）、§3.2（项目掌握度 vs 个人总体掌握度）、§5.2（`LearningContent` / `ContentRelation` / `ProjectContent`）；TAD §3.3

## 1. 职责与边界

**做什么**：

| 能力 | 表 | 状态 |
|---|---|---|
| 学习内容本体 CRUD（知识点 / 技能点 / 语言点，树形） | `learning_contents` | ⬜ 规划 |
| 内容间关系（前置 / 相关 / 包含 / 扩展 / 替代） | `content_relations` | ⬜ 规划 |
| 创建时相似内容提示（**不阻断**） | 查询 `learning_contents` | ⬜ 规划 |
| 内容加入项目 + 项目级目标等级 / 状态 | `project_contents` | ⬜ 规划 |
| 跨项目复用查询（「这份内容在哪些项目里、到哪一步了」） | 反向查 `project_contents` | ⬜ 规划 |
| 标签（自由标签 + 内容打标） | 缺表 | ❓ 未设计 |

**不做什么**（这些属其他模块，勿塞进本域）：

| 不做 | 归属 | 理由 |
|---|---|---|
| 掌握度评价（L0–L4 的判定与历史） | M06 | 本域只存「目标等级」与「粗粒度状态」，评价是独立事件流 |
| 复习调度 | M07 | 复习队列以 `project_content` 或 `content` 为作用域，但算法与状态归 M07 |
| 题库与错题 | M08 | ERD §12 第 2 项明确模型未锁定 |
| 学习活动记录 | M05 | 内容是「学什么」，活动是「什么时候学了多久」 |
| 文件上传 | 横切（`infrastructure/storage`） | `LocalStorage` 仍是 stub，内容含附件时被阻塞 |

## 2. 目录与文件形态

```text
modules/knowledge/            🟡 空 mod.rs
├── mod.rs                    # 待建
├── dto.rs                    # ContentItem / CreateContentRequest / UpdateContentRequest
│                             # ContentTreeQuery / SimilarContentHint
├── handler.rs                # 内容 CRUD、树形列表、相似提示
├── service.rs                # 内容 CRUD + 相似度查询
└── relation.rs               # 内容关系（前置/相关），独立于内容本体

modules/library/              🟡 空 mod.rs
├── mod.rs                    # 待建
├── dto.rs                    # ProjectContentItem / AttachContentRequest / UpdateProjectContentRequest
├── handler.rs
└── service.rs                # 关联、项目内状态迁移、跨项目复用查询
```

**为什么拆成两个模块**（这是本域唯一需要解释的边界）：

- `knowledge` 关心「这份内容是什么」。内容是**用户级资产**（`owner_id`），可跨项目复用。ERD §3.1 明确允许重复创建、只提供复用提示、**不建 `(owner_id, title)` 唯一约束**。
- `library` 关心「这个项目里这份内容到哪一步了」。状态是**项目级**（`project_contents.current_status` 与 `target_mastery_level`）。
- 同一份内容在两个项目里可以分别是 `learning` 与 `achieved`——这是 ERD §3.2 的核心区分。若合并成一个模块，必然出现「项目状态字段被多项目共享」的错，而这个错一旦写进表结构就很难纠正。

**命名风险**：`knowledge` 目录名与中文「知识库」的语义并不完全对应（它其实是「学习内容」）。若将来引入真正的知识库（笔记、双链、Zettelkasten），需要把现在的 `knowledge` 重命名为 `content`，把 `knowledge` 让出去。现在改成本低，越晚越贵。

| # | 待决策 | 影响 |

## 4. 调用链与分层

**创建内容（含相似提示）**：

```text
POST /api/v1/learning-contents
  request_id_middleware → auth_middleware → Extension<UserId>
  handler::create(State, Extension<UserId>, Extension<RequestId>, Json<CreateContentRequest>)
    → service::create(&db, user_id, req)
        1. SELECT id, title, similarity(title, $2) AS score
             FROM learning_contents
            WHERE owner_id = $1 AND content_type = $3 AND status = 'active'
              AND similarity(title, $2) > 0.4
            ORDER BY score DESC LIMIT 5
           -- 相似提示：只查，不阻断
        2. INSERT INTO learning_contents (…) RETURNING …
        3. 若 hints 非空 → 响应带 `similar_hints`（提示用户「可能重复，也可继续」）
```

**关键设计**：相似提示**同步查**，不能异步。异步意味着用户已建完才收到「你可能重复了」，提示变成噪音。代价是创建路径多一次查询，可接受（有 `(owner_id, content_type)` 索引）。

**内容加入项目**：

```text
POST /api/v1/project-contents
    → service::attach(&db, user_id, req)
        1. SELECT p.id, c.id FROM learning_projects p, learning_contents c
            WHERE p.id = $1 AND c.id = $2
              AND p.owner_id = $3 AND c.owner_id = $3
           -- 一次查询校验三方归属：项目、内容都属于当前用户
        2. 无行 → NotFound（不区分「项目不存在」「内容不存在」「不是你的」）
        3. INSERT … ON CONFLICT (project_id, content_id) DO NOTHING
           -- 幂等：重复关联不报错（UNIQUE 约束已存在）
```

**分层约束**：归属校验一律写进 SQL，不做事先 SELECT 再判断（`README.md` §6.2）。

## 5. 数据与不变量

**三张核心表（ERD §5.2）**：

| 表 | 关键字段 | 关键约束 |
|---|---|---|
| `learning_contents` | `owner_id`、`content_type`、`title`、`description`、`parent_id`（自引用）、`metadata` JSONB、`created_source`（`user / ai_confirmed / template`）、`status`（`active / archived`） | **不建 `(owner_id, title)` 唯一约束**（ERD §3.1 明文）；可建 `(owner_id, content_type)` 普通索引 |
| `content_relations` | `owner_id`、`source_content_id`、`target_content_id`、`relation_type`（`prerequisite / related / contains / extends / alternative`） | `source <> target`；`UNIQUE(source, target, relation_type)`；两端同 owner；`prerequisite` 新增时查环 |
| `project_contents` | `project_id`、`content_id`、`target_mastery_level`（0–4）、`current_status`（五值）、`priority`（1–5）、`auto_review_enabled`、`linked_at`、`achieved_at` | `UNIQUE(project_id, content_id)`；项目 owner 必须等于内容 owner |

**服务层必须保证的规则**：

| 规则 | 为何 DB 无法独立保证 |
|---|---|
| 内容树不得成环（`parent_id` 自引用） | 递归约束，SQL 表达成本高 |
| `prerequisite` 关系不得成环 | 图算法 |
| 两端内容同属一个 owner | 跨两表一致性；可用复合外键加强但需要冗余列，v1 走服务层 |
| 项目与内容同属一个 owner | 同上 |
| 树深度建议 ≤ 5 层（PRD §6.3「界面建议控制在 4–5 层以内」） | 这是**界面建议不是硬约束**，不应在 DB 层拒绝。若要做软提示，放在响应里返回 `depth` 由前端提醒 |

**模型缺口**：

| 缺口 | 说明 |
|---|---|
| **标签模型** | ERD 无 `content_tags` / `learning_content_tags`。PRD §6.3 明确要求「一个内容可以关联多个标签；一道题目可以关联多个知识点；一个实践成果可以关联多个技能点」——后两者靠外键已覆盖，标签完全缺失 |
| **内容正文** | ERD 只有 `metadata`（且注明仅放类型扩展属性）。若内容需要富文本/LaTeX/代码块，必须新增列或明确约定 `metadata.body` 的语义（但「扩展属性」与「正文」混放是坏味道） |

## 6. 状态与副作用

**`project_contents.current_status` 五值**：`not_started → learning → reviewing → achieved`，旁路 `waived`。

**不要照抄 ADR-007**。ADR-007 的统一迁移规则（允许跳过中间态、允许回退、终态不直转、同态幂等）是为「执行动作」设计的，而 `achieved` 在这里是**掌握结论**，不是完成动作：

| 差异点 | 阶段/任务（ADR-007） | 项目内容（本域） |
|---|---|---|
| `achieved` 的性质 | 完成动作的结果 | 掌握判定的结论，须有证据支撑（M06） |
| 能否由用户直接置位 | 能（`complete` 动作） | **不应**由用户手改；应由 M06 的评价结果驱动，或用户显式确认 |
| 回退语义 | 离开 completed 即清 `completed_at` | 回退到 `learning` 应保留 `achieved_at` 作为「曾经达成」的记录，还是清空？未定 |
| `waived` | 无对应物 | 永久放弃，应保留理由 |

**建议**（待决策 6）：`current_status` 只允许用户改 `not_started ↔ learning ↔ reviewing` 与 `→ waived`；`achieved` **只能由 M06 写入**（评价确认后置位，同时写 `achieved_at`）。这样避免「用户手点一下就算掌握」的伪造。

**副作用**：

| 动作 | 写入 |
|---|---|
| 内容创建 | `created_source`（`user` / `ai_confirmed` / `template`）；AI 生成的必须是 `ai_confirmed` |
| 加入项目 | `linked_at = now()`；`current_status` 默认 `not_started` |
| 置 `achieved` | `achieved_at = now()`（只写一次，不随回退清空） |
| 解除关联 | 物理删除 `project_contents` 行；**不删内容本体**（其他项目可能还在用） |
| 内容归档 | `status = archived`；不影响已关联的项目上下文 |

## 7. 错误映射

| 场景 | 变体 | HTTP | 备注 |
|---|---|---|---|
| 内容不存在 / 非本人 | `NotFound` | 404 | |
| 项目不存在 / 非本人（关联时） | `NotFound` | 404 | 与「内容不存在」不可区分 |
| 内容树成环、`prerequisite` 成环 | `Validation` | 422 | |
| 两端内容跨用户 | `Validation` | 422 | 理论上不可达（都查了 owner），做防御 |
| 重复关联同一内容到同一项目 | **幂等 200** | 200 | `UNIQUE` + `ON CONFLICT DO NOTHING`，不返回 409 |
| 手改 `current_status` 为 `achieved` | `Conflict` | 409 | 建议（待决策 6） |
| 内容被引用时删除 | `Conflict` | 409 | 带影响面（`data.impact`），与 ADR-006 的级联确认对齐 |

## 8. 事务边界

| 操作 | 事务 |
|---|---|
| 内容 CRUD | 单语句 |
| 内容 + 关系同时写入 | 单事务（关系建失败则内容不该留下） |
| 关系成环检测 | 单事务：查环 → 插入，防并发成环（与 `task_dependencies` 同构） |
| 加入项目 | 单语句 + `ON CONFLICT`，无需事务 |
| 内容删除 | 单事务：校验引用 → 删 `content_relations`（两端）→ 删 `project_contents` 或 409 |

**注意**：`content_relations` 删除要处理**两个方向**——内容 A 被删时，`source_content_id = A` 与 `target_content_id = A` 的行都要清理。只删一边会留下悬空引用。
