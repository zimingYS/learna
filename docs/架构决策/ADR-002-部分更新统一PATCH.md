# ADR-002 部分更新统一采用 PATCH

**状态：** 已采纳（2026-11-27）  
**范围：** HTTP 方法语义（全局）

## 背景

学习记录更新接口使用 `PUT`，但请求 DTO 字段全部可选，实际语义是部分更新——与 PUT「全量替换」的语义错位。两条出路：改用 PATCH，或让 PUT 要求提交完整资源。TAD §6.1 明确「PATCH 明确区分字段缺失、显式 null 和具体值」。

## 决策

1. **部分更新一律用 PATCH**；PUT 保留给未来「整体覆盖」场景（当前无使用）。
2. PATCH 三态语义为正式契约规范：字段**缺失**＝保持不变；显式 **null**＝置空；**值**＝更新。
3. 现有 `/api/v1/records/{id}` 由 PUT 改为 PATCH（前端 api 封装、集成测试已同步）。
4. 过渡接口的 `UpdateRecordRequest` 当前为二态（`Option<T>`：缺失与显式 null 均视为不修改，`content` 无法置回 NULL）——与三态的差距已记录在 `接口契约/设计记录/现有接口审计.md`，是否提前升级 `Option<Option<T>>` 属**待决策**。

## 后果

- 正面：动词语义与请求形态一致；与 TAD 契约原则对齐；为正式 LearningSession 的 PATCH 契约立下全局约定。
- 负面：PUT→PATCH 对既有调用是破坏性变更——pre-release 内部调用方已全部同步。
- 正式资源实现 PATCH 时必须实现三态（含显式 null 置空），不得沿用过渡实现的二态。
