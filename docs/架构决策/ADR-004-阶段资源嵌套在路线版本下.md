# ADR-004 阶段资源嵌套在路线版本路径下

**状态：** 已采纳（2026-11-27）
**范围：** 学习规划模块 REST 路径（Stage 归属关系）

## 背景

TAD §6.3 的资源分组示例把阶段放在项目下：`/api/v1/projects/{id}/stages`。

但 ERD §5.1 中 Stage 的归属字段是 `roadmap_id`（`FK -> Roadmap`），且 Roadmap 是**版本化**实体：同一项目存在多个版本（`draft` / `active` / `superseded`），`UNIQUE(project_id, version)` 且「一个项目最多一个 active」。

若 Stage 挂在项目级路径下，仅凭 `stage_id` 无法表达「属于哪个路线版本」，会出现两类问题：

1. **版本隔离失效**：对 `superseded` 路线的阶段与 `active` 路线的阶段无法从路径区分，权限与可编辑性判断（superseded 只读）必须回查数据库才能确定。
2. **创建语义含糊**：`POST /projects/{id}/stages` 无法表达新阶段写入哪个版本，必然要求把 `roadmap_id` 塞进请求体，与路径表达的资源层级不一致。

TAD §11.10 已明确「最终路径应在领域模型确定后冻结」，即 §6.3 的分组示例不构成最终约定。

## 决策

阶段路径嵌套在路线版本下：

```
/api/v1/projects/{project_id}/roadmaps/{roadmap_id}/stages
```

- 路径同时携带项目与路线两级标识，服务端可据此校验「阶段属于该路线、路线属于该项目」，任一层不匹配返回 404。
- 创建阶段不再需要请求体传 `roadmap_id`。
- 阶段动作端点同层级展开（`/stages/{stage_id}/start|complete|skip|reactivate`）。

同时明确其余资源的挂载层级：

| 资源 | 路径 | 理由 |
|---|---|---|
| ProjectGoal | `/projects/{project_id}/goals` | 强属项目（ERD FK） |
| Roadmap | `/projects/{project_id}/roadmaps` | 版本历史需按项目查询 |
| Milestone | `/projects/{project_id}/milestones?stage_id=` | 扁平项目级 + 过滤；`stage_id` 在创建时必填 |
| LearningTask | `/projects/{project_id}/tasks` | `milestone_id` 可空，避免五层嵌套 |
| TaskDependency | `/projects/{project_id}/tasks/{task_id}/dependencies` | 依赖以任务为主语 |

## 后果

- 正面：路径即归属，版本隔离与只读判定可在路由层完成；创建语义无歧义；与 ERD 的 `roadmap_id` 归属一致。
- 负面：阶段端点路径较长（5 段）。权衡后接受——阶段操作频率低于任务，且省去请求体传父标识的隐患。
- 若后续引入「跨版本阶段复用」（ERD 未定义），需重新评估本决策。
- 契约落盘位置：`docs/接口契约/openapi.yaml` 与 `docs/接口契约/设计记录/学习规划模块契约设计.md` §3。
