# 测试与验证

## 1. 测试原则

重要业务逻辑必须有测试。测试必须验证真实行为，而不是只验证代码能够执行。

优先覆盖：

- 正常路径
- 异常路径
- 边界条件
- 权限边界
- 用户数据隔离
- 数据一致性
- 历史数据保护
- 并发与事务边界（适用时）

## 2. 测试质量

禁止：

- 删除失败测试来使 CI 通过。
- 通过跳过必要校验掩盖问题。
- 使用无意义断言。
- 使用与实际业务无关的 Mock 结果。
- 将未执行的测试报告为通过。
- 只测试 Handler 而完全忽略核心业务规则。

Mock 可以用于隔离外部依赖，但核心业务规则应尽可能通过真实逻辑验证。

## 3. 验证命令

根据任务类型执行适当检查，实际命令以仓库现有配置为准。

### Rust

```bash
cargo fmt --check
cargo check
cargo clippy
cargo test
```

### Frontend

```bash
npm run lint
npm run type-check
npm run test
npm run build
```

如果某项脚本未配置，以仓库实际配置为准并说明。

### Python

```bash
ruff check
ruff format --check
pytest
```

必要时执行类型检查。

### Integration

根据实际环境运行：

- PostgreSQL Migration Tests
- API Integration Tests
- OpenAPI Contract Tests
- Docker Build
- End-to-End Tests

如果某项检查因为环境或依赖问题无法执行，必须明确说明，不能伪造通过结果。
