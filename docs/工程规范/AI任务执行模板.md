# AI 任务执行模板

本文规定项目内 AI 任务的**输入**（任务发起人如何下任务）与**交付**（AI 如何交差）规范。执行过程的硬约束见 `docs/AGENTS.md`，交付报告格式见 `docs/工程规范/交付报告模板.md`，本文不重复其内容。

## 1. 适用范围

- 适用于所有由 AI Agent 执行的编码、重构、文档、配置类任务（人类贡献者可参考使用）。
- 一个任务 = 一次可独立验收的工作单元；过大的目标先拆分再派发。

## 2. 任务输入

### 2.1 任务单模板

发起人按以下格式提供任务。字段可裁剪，但**背景、目标、范围、验收标准**四项缺省时 AI 必须先澄清，不得猜测。

```markdown
## 任务：〈一句话目标〉

- **背景**：为什么做，前置状态是什么。
- **目标**：本次要达成的效果，一句话可验证。
- **范围（做）**：涉及的模块 / 文件 / 接口清单。
- **非目标（不做）**：明确不碰的部分，防止范围蔓延。
- **验收标准**：可勾选的完成判据（命令通过 / 行为正确 / 文档同步等）。
- **约束与参考**：相关设计文档路径、必须遵守的规范、方案 A/B 待拍板项。
- **授权级别**：指导（只出方案与 review）/ 实施（直接改代码）。
```

### 2.2 输入质量要求

- **目标可验收**：「优化登录」不可验收，「登录失败时表单展示后端 message 且不跳转」可验收。
- **范围封闭**：给出「做/不做」边界；模糊边界按 `docs/AGENTS.md` §10 停止条件处理。
- **参考给路径**：引用文档、文件、接口必须给具体路径或名称，不写「参考设计文档」。
- **待拍板项写明选项**：需要决策的点列出 A/B 方案及倾向，等发起人拍板后再动手。

### 2.3 任务单示例

```markdown
## 任务：learning_record 增加按科目筛选

- **背景**：列表接口已上线（GET /api/records），前端 RecordsView 可用。
- **目标**：列表支持按 subject 精确筛选，前后端打通。
- **范围**：backend service/handler/dto（records 模块）、frontend api/records.ts + RecordsView 筛选控件。
- **非目标**：不做模糊搜索、不做多选筛选、不改迁移。
- **验收标准**：
  1. GET /api/records?subject=math 仅返回 math 记录；
  2. 前端选择科目后列表刷新，清空后恢复全量；
  3. cargo test 与 npm run check 全绿；
  4. 接口契约文档同步。
- **约束与参考**：docs/工程规范/数据库与API规则.md；查询参数命名 snake_case。
- **授权级别**：实施。
```

## 3. 执行规则（摘要）

完整规则以 `docs/AGENTS.md` 为准，要点：

1. **编码前**：阅读规范与现有实现，明确范围；未检查现有代码不得新建重复实现。
2. **中大型任务**：先提交实施方案（目标 / 文件清单 / 数据库与 API 影响 / 测试方案 / 风险），获批准后实施；低风险局部修改可直接执行但不得扩大范围。
3. **编码中**：只改任务相关内容，复用现有实现，延续现有风格，同步必要文档。
4. **编码后**：Git Diff 自查 → 跑格式 / 静态检查 / 测试 → 按交付报告模板交差 → 停止，等待下一项任务。
5. **停止条件**（`docs/AGENTS.md` §10）触发时暂停并报告：设计冲突、改公共契约、核心库结构变更、新核心依赖、业务规则不明、不可逆操作等。

## 4. 交付规范

### 4.1 交付报告

任务完成后必须按 `docs/工程规范/交付报告模板.md` 提供完整交付报告（九节：任务摘要 / 修改文件 / 实现细节 / 代码质量 / 数据库与 API 变更 / 测试结果 / 已知问题 / 设计偏差 / 下一步）。

- **测试结果必须真实执行**，区分通过 / 失败 / 跳过 / 未执行，禁止未跑先报。
- **数据库与 API 变更**无变化时明确写「无」。
- **下一步**只建议、不擅自开工。

### 4.2 代码交付

- 构建、格式、静态检查、测试全绿（命令清单见 `docs/开发指南/本地开发环境.md` 第 5 节）。
- 无无关文件改动、无调试残留、无未使用代码。
- 涉及 API / 数据库 / 领域规则的变更，对应文档已同步更新。
- 交付物为文档时，遵守文档同步规则（`CONTRIBUTING.md` §6）。

### 4.3 验收与关闭

1. 发起人对照任务单「验收标准」逐项核对。
2. 未达标项退回并说明差距，AI 修复后重新交付。
3. 验收通过即关闭任务；遗留问题另开任务单，不无限追加。
4. 任务完成后 AI 停止，**不得擅自开始下一项任务**。
