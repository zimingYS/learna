# 变更管理

## 1. 范围控制

每个任务必须有明确边界。不得：

- 擅自修改无关模块。
- 顺手重构大量旧代码。
- 删除未确认的功能。
- 改变公共接口。
- 擅自改变领域模型。
- 引入无关依赖。
- 修改许可证。
- 将当前任务扩展为无关功能开发。

如果发现任务范围之外的问题，记录并单独提出。

## 2. 依赖管理

新增依赖前必须说明：

- 为什么需要。
- 现有依赖为什么无法满足。
- 是否有更轻量的替代方案。
- 对构建、运行和维护的影响。

未经批准，不得随意增加大型依赖。

## 3. 重构

重构必须具有明确目标。重构过程中：

- 尽量保持对外行为不变。
- 保留现有测试。
- 不得将重构与无关功能混在一个任务中。
- 先确保旧功能可验证，再进行结构调整。
- 及时清理真正不再使用的旧实现。

## 4. Git 工作流

遵循项目 `CONTRIBUTING.md`。分支类型：

- `main`：稳定主分支
- `feat/*`：功能开发
- `fix/*`：问题修复
- `refactor/*`：重构（不改变外部行为）
- `docs/*`：文档变更
- `chore/*`：工程维护

协作规则：

- 遵循 Conventional Commits，所有变更通过 Pull Request 合并，统一 Squash and Merge。
- 合并前必须 CI 全绿，并获得至少 1 名审查者批准（1 required approval）；PR 作者不能批准自己的 PR。
- 敏感路径（`.github/`、`deploy/`、`backend/migrations/`、`.env.example`、`LICENSE`）的变更由 `CODEOWNERS` 负责人审查。
- 不得未经批准直接向 `main` 推送代码。
