# 领域模型不变量

必须遵守已确认的 Learna 领域设计。修改以下规则必须先提交 ADR 或设计变更说明。

权威来源：`docs/数据库设计/Learna领域模型与ERD设计文档V1.0.md`（领域模型与 ERD）、`docs/产品需求/Learna产品需求规格说明书V1.0.md`（需求基线）。本文件是不变量摘要，与来源文档冲突时以来源文档为准并暂停报告。

## 1. Learning Content

- 学习内容允许重复创建。
- 相似内容可以提示用户复用。
- 不强制 owner + title 唯一。
- 学习内容允许跨项目共享。

## 2. Project Context

每个项目拥有独立的：

- 学习计划
- 学习目标
- 目标掌握等级
- 项目上下文掌握状态
- 复习状态

个人总体掌握度与项目上下文掌握度必须分离。

## 3. Learning Records

必须区分：

- LearningSession：实际发生的学习事实。
- ScheduledActivity：计划活动。
- LearningTask：待完成工作项。

三者不可合并。

一条 LearningSession：

- 拥有一个主要项目。
- 可以关联多个其他项目。
- 可以关联多个知识点或技能点。
- 可以不关联任务。
- 可以与多个任务建立关联。

只有主要项目计入学习时长，关联项目不得重复累计。

## 4. Mastery

- 掌握度采用 L0-L4。
- 系统评价与用户自评共同参与掌握度认定。
- 保留掌握度历史。
- 不得静默覆盖历史评估。
- 个人总体掌握度与项目上下文掌握度分离。

## 5. Review

- 默认按项目独立进行复习调度。
- 支持显式共享复习结果。
- 共享结果默认作为参考证据。
- 不得静默覆盖目标项目的复习调度状态。

## 6. Questions

错题必须拥有独立领域模型。题库、练习、错题记录和 AI 生成题目应保持清晰边界。

## 7. Project Lifecycle

- 项目删除默认采用归档策略。
- 彻底删除需要额外确认。
- 项目允许没有阶段。
- 支持多个最终目标。
- 阶段可以跳过、提前进入或返回。
- 软截止日期允许调整。
- 固定事件不能被当作普通软截止日期延期。

## 8. Scheduling

- 用户每日学习时间是目标，不是强制上限。
- 每日学习时长支持按日期自定义。
- 默认均衡安排。
- 支持复习优先和用户自定义复习日期。
- 超出预算时推荐调整方案，由用户确认。
- 不得硬编码考试日期或特定学习周期。
