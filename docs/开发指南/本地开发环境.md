# 本地开发环境

本文说明 Learna 本地开发环境的搭建、配置与服务启动。命令均在项目根目录执行；如与根 `README.md`「快速开始」不一致，以本文为准并同步修正 README。

## 1. 前置工具

| 工具 | 版本要求 | 用途 |
|---|---|---|
| Git | 最新版 | 版本管理 |
| Rust | stable（rustup） | backend |
| Node.js | 20+ | frontend（包管理使用 npm） |
| Python | 3.11+（推荐 uv） | ai-service |
| Docker | 最新稳定版 | 开发数据库 / 全栈部署 |

## 2. 获取代码与环境变量

```bash
git clone <repo-url> learna && cd learna
cp .env.example .env
```

`.env` 为本地私有配置，已被 `.gitignore` 忽略，**不得提交**。必填/关键变量：

| 变量 | 说明 | 示例 |
|---|---|---|
| `APP_ENV` | 运行环境 | `dev` |
| `DATABASE_URL` | PostgreSQL 连接串 | `postgres://learna:devpass@localhost:5432/learna` |
| `JWT_SECRET` | JWT 签名密钥 | `openssl rand -hex 32` 生成 |
| `AI_SERVICE_BASE_URL` | AI 服务地址 | `http://localhost:8001` |
| `AI_SERVICE_TOKEN` | 内部服务凭据，backend 与 ai-service 必须一致 | `openssl rand -hex 32` 生成 |
| `STORAGE_PROVIDER` / `STORAGE_ROOT_DIR` | 本地文件存储 | `local` / `./data/uploads` |

缺必填变量启动时后端报 `missing required env: <NAME>`，按提示补齐即可。

## 3. 启动开发数据库

```bash
docker compose -f deploy/compose.dev.yaml up -d
```

- 仅启动 PostgreSQL 16，凭据固定 `learna / devpass`，库名 `learna`，与 `.env.example` 默认值对齐。
- compose 项目名钉死为 `learna-dev`，不会与其他 compose 栈合并。
- **端口冲突**：映射宿主 `5432`。若宿主机已有 PostgreSQL 占用 5432，先停宿主实例，或改 `compose.dev.yaml` 的端口映射并同步 `.env` 中的 `DATABASE_URL`（正式部署 `deploy/compose.yaml` 映射 5433 就是为避让宿主 5432）。

数据库表结构由 backend 启动时 SQLx Migration 自动建，无需手工建表。

## 4. 启动服务

三个服务分三个终端启动：

```bash
# 后端（端口 8080）
cd backend && cargo run

# AI 服务（端口 8001，仅内网，浏览器不可直连）
cd ai-service && uv sync
uv run uvicorn app.main:app --reload --port 8001

# 前端（端口 5173）
cd frontend && npm install && npm run dev
```

### 端口分配

| 服务 | 端口 | 网络边界 |
|---|---|---|
| frontend（Vite dev） | 5173 | 本机 |
| backend（Rust API） | 8080 | 对浏览器开放 |
| ai-service（FastAPI） | 8001 | 仅内网 |
| PostgreSQL（dev） | 5432 | 仅服务端访问 |

### 启动验证

```bash
curl http://localhost:8080/api/healthz   # 应返回 code:"200" 的统一信封
```

浏览器访问 `http://localhost:5173` 应打开前端页面。

## 5. 质量工具命令

提交前必须通过对应栈的检查（CI 同款）：

| 栈 | 用途 | 命令 |
|---|---|---|
| backend | 格式 | `cargo fmt --check` |
| backend | 静态分析 | `cargo clippy --locked -- -D warnings` |
| backend | 测试 | `cargo test --locked` |
| ai-service | 格式 | `uv run ruff format --check app tests` |
| ai-service | 静态分析 | `uv run ruff check app tests` |
| ai-service | 测试 | `uv run pytest` |
| frontend | 类型检查 | `npm run type-check` |
| frontend | 静态分析 | `npm run lint` |
| frontend | 测试 | `npm test` |
| frontend | 一键全检 | `npm run check` |

## 6. 全栈部署模式（可选）

不逐个起服务时，可用正式 compose 一键起全栈（postgres + backend + ai-service + frontend nginx）：

```bash
cd deploy && docker compose up -d --build
```

与开发模式的区别：backend/ai-service 跑在容器内、前端走 nginx 静态托管、PostgreSQL 映射宿主 5433。日常开发建议用第 4 节的分服务方式（支持热重载）。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `missing required env: ...` | `.env` 未复制或变量缺失，对照 `.env.example` 补齐 |
| 数据库连接失败 / 认证失败 | dev 库未启动，或宿主 5432 被占用；见第 3 节 |
| backend 调 ai-service 401 | 两侧 `AI_SERVICE_TOKEN` 不一致，统一后重启 |
| 8080 被占用 | 检查占用进程（如 Steam web helper），或改 `APP_PORT` 并同步前端代理配置 |
| `uv run` 拉包超时 | 网络代理限速，`UV_HTTP_TIMEOUT=120` 重试 |
